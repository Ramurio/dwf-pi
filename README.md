# dynamicwf-pi

Собирайте агентные процессы из блоков и связей, запускайте независимых исполнителей pi
и наблюдайте результат в браузере или терминале. Поддерживаются условия, циклы
доработки по ревью, параллельные ветки, динамическое разветвление по массиву данных
и вложенные графы. Закрытие чата, управляющего приложения или монитора не останавливает запуск.

## Установка

Нужны **Node >=22.19.0**, Git и локальная POSIX-среда (macOS/Linux).
В каталоге репозитория выполните:

```sh
npm ci
npm run sdk:check
npm run setup
dynamicwf system.doctor
dynamicwf catalog.models
```

Установщик создаёт ссылки `~/.local/bin/dynamicwf` и `~/.agents/skills/dynamic-workflows`.
Добавьте `~/.local/bin` в `path`, если его там нет. Копия репозитория и её `node_modules`
остаются установленным приложением. Авторизация моделей берётся из локального pi;
установщик её не создаёт. Выбирайте точные `provider`/`model`/`thinking` из `catalog.models`,
а не название подписки. [Другие пути установки и подключение агента](PROJECT_INFO/models-and-setup.md#установка-команды-и-skill).

## Дать задачу агенту

Агенту нужен установленный пакет инструкций (skill)
[dynamic-workflows](skills/dynamic-workflows/SKILL.md) и доступ к командной оболочке или MCP. Например:

> Используй dynamic-workflows. Собери граф: планирование, реализация в отдельном
> `worktree`, тесты, независимое ревью и доработка до одобрения. Модели выбери из
> каталога. После старта сразу дай ID запуска и команду watch. Сохранять пресет не нужно.

Для трёх независимых исследователей с общим итогом есть готовый
[рецепт research-trio](skills/dynamic-workflows/recipes/research-trio/README.md).
Другой пример — [совет независимых ревьюеров](PROJECT_INFO/authoring.md#council).
Граф создаётся инструментами до запуска; писать планировщик или JS-оркестрацию не нужно.

CLI принимает один JSON-запрос через stdin. MCP запускается командой `dynamicwf mcp`
и предоставляет тот же интерфейс.

```sh
dynamicwf workflow.create <<'JSON'
{"id":"my-flow","name":"My workflow"}
JSON

dynamicwf workflow.schema <<'JSON'
{}
JSON
```

После добавления узлов и проверки графа `workflow.prepare` фиксирует настройки
и возвращает `preparedId`. `run.start` с этим ID и заранее выбранным `idempotencyKey`
запускает план; повторная доставка того же запроса возвращает тот же запуск.
[Порядок запуска](PROJECT_INFO/execution-plan.md#prepared-start).

## Смотреть и управлять

```sh
dynamicwf ui                    # открыть/найти фоновую панель
dynamicwf ui --install          # на macOS: запуск панели при входе в систему
dynamicwf watch --run <run-id>   # терминальный монитор
```

Постоянная закладка по умолчанию: **http://127.0.0.1:4380/**.
В панели доступны старые и новые запуски, граф, история, фактические переходы,
токены, причины остановки и ответы на ожидания. `dynamicwf ui --run <run-id>`
печатает ссылку на конкретный запуск. [Настройка панели](PROJECT_INFO/observation.md#browser-ui).

```sh
dynamicwf run.list <<'JSON'
{}
JSON

dynamicwf run.pause <<'JSON'
{"id":"run-ID"}
JSON
```

Для продолжения используйте `run.resume`, для отмены — `run.cancel` с тем же JSON.
Пауза дожидается текущих исполнителей и запрещает новую работу; отмена прерывает их.
Закрытие watch или вкладки только отключает просмотр.

По умолчанию данные хранятся в `~/.dynamicwf/state.sqlite`.
`DYNAMICWF_HOME` меняет каталог состояния, `--store /path/state.sqlite` — журнал.
Во всех командах одного запуска используйте одну базу.

## Результаты и ограничения

- Статус `succeeded` означает завершение графа. Принятие задачи определяется
  отдельно по `taskOutcome.decision`: `accepted`, `rejected` или `inconclusive`.
- Токены — сохранённые отчёты SDK. Неизвестный расход не считается нулём;
  эти числа не являются счётом или остатком подписки.
- После аварии неопределённые внешние действия не повторяются молча.
  Используйте [инспекцию и явное восстановление](PROJECT_INFO/reconciliation.md).
- Граф работающего запуска неизменяем. Для пересмотра той же задачи существует
  связанное продолжение; старый результат и история сохраняются.
- Параллельная запись кода требует отдельных рабочих деревьев Git; слияние — явный `integrate`.
- Разрешения инструментов и рабочие деревья не изолируют права ОС: команды имеют права пользователя.
- По умолчанию нет скрытых лимитов итераций, стоимости, времени или обязательных
  человеческих согласований. Политика задаётся графом.
- Пресеты сохраняются только явно из принятого запуска; доступны проектная и
  глобальная библиотеки. [Работа с пресетами](PROJECT_INFO/authoring.md#presets).
