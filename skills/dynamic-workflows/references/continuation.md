# Связанное продолжение задачи

Читай перед запуском пересмотренного графа той же задачи или повторным использованием
успешных выходов. Не заменяй неудачный/незавершённый запуск несвязанным `start` со скопированным
JSON. Повтор неопределённой **исходной операции** требует [восстановления](recovery.md)
и `run.reconcile`; продолжение задачи эти проверки не обходит.

## Инспекция и создание

Вызови `run.continuation.inspect {"id":"run-..."}`, подготовь новый граф, затем `run.continue`:

- `preparedId` нового плана;
- заранее выбранный обязательный `idempotencyKey` из общего с `run.start` пространства
  журнала: ключ `start` нельзя перепривязать к continuation и наоборот;
- точный `source` `{runId,checkpoint,planHash}`;
- `workspaceDigest` свежей инспекции;
- непустые `actor`/`reason`/`evidence`;
- `input` и точные привязки `reuse`, если используются.

`run.continue` немедленно возвращает новый ID запуска — сразу сообщи его и команду watch.
Точная повторная доставка возвращает тот же запуск до перечитывания каталога;
конфликтующий запрос не создаёт новый. Инспекция сама не разрешает действий.

## Что не меняется

Продолжение не редактирует исходный план, не повторяет записи, не снимает исходную
паузу и не обходит восстановление. Создание преемника не является `run.resume` источника;
источник на паузе даёт продолжение на паузе. История/исходная ошибка сохраняются,
старому запуску нельзя ответить на новый `await` после допущенного продолжения.

Неизвестные эффекты записи требуют явного `disposition` `retain-effects`, привязанного
к `key`/`attempt`, с непустым `evidence`. Оно **сохраняет** прежние эффекты, не означает
`accept`, `retry` или право повторить пишущий узел. Для исходной операции нужен `run.reconcile`.

## Повторное использование результата: `reuse`

Узел `reuse` (`bindingId`, строгая объектная `outputSchema`) нужен только для происхождения
уже успешного выхода. Он возвращает точный снимок без модели; `run.start` отвергает план
с `reuse`. Привязка выбирает `sourceRunId`/`activationKey`/`attempt` из инспекции, не отображаемого
имени. При наличии передаются `sourceOutputDigest`/`sourceSchemaDigest`/`producerSchemaDigest`
и привязки версий.

Повторно используемый ревьюер сохраняет `artifactRevision` и `acceptanceCriteriaRevision`
при наличии. Старый `approve` не одобряет другой артефакт/версию критериев: привязку
нельзя выдумать. `reuse` не добавляет токены. `task.inspect`/`task.usage` показывают связанные
запуски, изменение плана, квитанции и суммарный расход SDK; [учёт](usage.md).
