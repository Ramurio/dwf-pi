# Наблюдение и управление

После создания запуска можно наблюдать, инспектировать, ставить на паузу, отвечать
`await` и явно сохранять пресеты. Старт использует `preparedId` и сохранённый `idempotencyKey`;
настоящий ID запуска и команду watch выдай сразу после `start`. Закрытие просмотра
не отменяет запуск.

## Watch и браузер

Сразу дай `dynamicwf watch --run <id>` с реальным ID и --store при нестандартной БД,
**до ожидания**. `dynamicwf ui --run <id>` с тем же журналом печатает локальный URL:
граф, ветки, текущая работа, история, токены и пауза/продолжение/отмена. Команда выходит,
постоянная панель остаётся в фоне; повтор использует её. Закладка по умолчанию:
http://127.0.0.1:4380/, конкретный запуск — `?run=<id>`; при другой настройке бери
напечатанный адрес. `dynamicwf ui --install` по запросу включает запуск при входе
в macOS. Для временного просмотра другой БД — `--foreground --port 0`.
Закрытие браузера/панели не останавливает графы.

Watch: 1 — сейчас, 2 — история, 3 — граф, 4 — токены; стрелки прокручивают, q/Ctrl+C
отсоединяют монитор. --once — компактный снимок, --`graph` --once — технический граф.
Для своего наблюдения предпочитай короткие `run.status` и раскрывай детали по необходимости,
не печатай полный граф многократно. Токены — записанные отчёты; активные/отсутствующие
ответы делают учёт неполным. Стоимость SDK не равна списанию подписки: [учёт](usage.md).

## Статус, события и трасса

`run.status` наблюдает, `run.inspect` возвращает выходы/активации;
`run.events {"id":"...","after":0}` даёт `events`/`nextAfter` для следующего чтения.
Технический `succeeded` — граф завершён; `taskOutcome.decision`/`reason`/`evidence` определяют
приёмку. Произвольный старый выход — `unclassified`. `evidence` — объявленные JSON-ссылки/
результаты, не машинно подтверждённые доказательства артефактов.

`run.trace {"id":"run-...","after":0,"limit":100}` объясняет реальные переходы:
исходную активацию/область/посещение, индекс ребра, `true`/`false`/`not-evaluated` после
первого совпадения, ошибки маршрутизации. Читай `nextAfter` пока `hasMore`. «Трасса» ведёт
к источнику на графе. Выбранное ребро не доказывает старт цели. Старые планы явно
сообщают отсутствие поддержки: не восстанавливай недостающие причины из цветов,
не называй непосещённый узел «пропущенным» без факта.

`run.collections {"id":"run-...","key":"parent-activation-key","after":0}` читает
сохранённые элементы `collect`/итоги; детали родителя в браузере используют те же записи.

## Пауза, продолжение и отмена

`run.pause` закрывает новый допуск и дожидается активных листьев, затем `paused`;
структурные `map`/`parallel` могут остаться записанными `running`. `run.resume` продолжает
живой supervisor либо восстанавливает подтверждённо умерший. `run.cancel` прерывает
исполнителей и необратим для запуска. Таймаут клиента, закрытая вкладка или старый
heartbeat не доказывают смерть: инспектируй существующий запуск вместо дубликата.
Перед повтором работы читай [восстановление](recovery.md).

## Ожидания

`await` принимает выражения непустой `reason` и `input`, строгую объектную `responseSchema`;
выход — проверенный ответ для обычных рёбер/привязок. Ожидание сохраняется независимо
от приложения, другие ветки продолжают работу. `inconclusive` `finish` завершает без
принятия; `await` оставляет открытым, но не означает одобрение.

При `waiting` прочитай `run.waits {"id":"run-..."}` и контракт ответа. Когда нужное
**реальное** доказательство получено, ответь
`run.resolve {"id":"run-...","waitId":"wait-...","response":{...},"resolvedBy":"agent"}`.
Участником может быть уполномоченный агент или пользователь браузера; обязательного
человеческого этапа нет. Одинаковый ответ идемпотентен, конфликтующий отвергается.
Ответ не снимает паузу; после подтверждённой смерти supervisor resolve может заново
запустить **тот же** граф и восстановить завершённые контрольные точки. `resume` сам
ответа не даёт. После продолжения задачи источник не принимает новый ответ; точный
дубликат записанного остаётся идемпотентным без перезапуска источника.

## Попытки и операции

`run.attempts {"id":"run-id","key":"activation-key","after":0}` использует точный `key`
из `run.inspect`. `records` — архив, `current` — отдельное живое наблюдение, не двигающее
курсор архива. Читай ошибки/учёт попытки; `missingArchived` отмечает никогда не сохранённую
историю. Чтение не разрешает повтор/восстановление. В браузере: узел → «Попытки».

`metadata.operation` при наличии содержит фактические `task`/`input` агента и намеченные
каталоги сессии/ресурсов, команду/аргументы `check`, источник/`childResult` `worktree` либо
источники/назначение/прогресс слияния `integrate`. «Операция этой попытки» раскрывает их явно.
Это намерение/наблюдения, не доказательство завершённого внешнего эффекта: нужны реальные
файлы/процессы и [восстановление](recovery.md).

## Явные пресеты

План с `reuse` нельзя сохранить как самостоятельный пресет: ему нужны подтверждённые
результаты конкретного исходного запуска. Для продолжения используй `run.continue`;
для повторяемого процесса создай и проверь граф без `reuse`. Исторические пресеты с
такими узлами остаются читаемыми, но обычный `preset.run` не воспроизводит их старые результаты.

Сохранение требует `succeeded` **и** `accepted`. `rejected`/`inconclusive`/`unclassified` не
становятся проверенными пресетами. После принятого запуска:
`preset.save {"id":"run-...","name":"review-council","scope":"project","cwd":"/workspace"}`.
`scope` `global` нужен для других проектов; автоматического сохранения нет. `preset.list`/
`inspect`/`run` поддерживают `scope`/`revision`; без `scope` проектное имя имеет приоритет
над глобальным. Запускай с новым `input`/`cwd`. Пресет содержит конкретные модели и
зафиксированные `skills`, не подменяет их изменёнными настройками по умолчанию.
`preset.run` создаёт новые сессии и не использует старые выходы.

Сообщай фактическое состояние/результат/доказательства и нерешённую работу. Валидный
граф, созданный supervisor и `succeeded`-запуск — разные исходы; только последний
доказывает завершение исполнения, принятие определяется отдельно.
