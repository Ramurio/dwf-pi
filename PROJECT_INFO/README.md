# Документация dynamicwf-pi

[README для пользователя](../README.md) — назначение, установка и основные сценарии.
[AGENTS](../AGENTS.md) — краткий вход для агента. Здесь — контракты действующего проекта,
границы реализации и воспроизводимые проверки, а не история отдельных запусков.

## Маршрут первого знакомства

1. [Архитектура](architecture.md): путь задачи и ответственность модулей.
2. [Установка и модели](models-and-setup.md): CLI, инструкции агента, авторизация, возможности и диагностика.
3. [Создание графа](authoring.md): операции, совет ревьюеров, пресеты и подготовка материалов.
4. [План и запуск](execution-plan.md): что зафиксировано, `preparedId` и безопасная доставка запроса.
5. [Наблюдение](observation.md): браузер, терминальный монитор, трасса и расход.

Переносимый [skill dynamic-workflows](../skills/dynamic-workflows/SKILL.md) поставляется
со своими справочными материалами и [рецептом research-trio](../skills/dynamic-workflows/recipes/research-trio/README.md).
Его можно установить/скопировать без PROJECT_INFO и копии репозитория. Вспомогательные
Markdown-файлы и JSON-рецепт остаются внутри skill, не дублируются здесь.

## Как пользоваться проверками

Команды из раздела разработки выполняются из корня репозитория. Ссылки на тесты
описывают их назначение, а не утверждают, что их запускали для любого текущего дерева.
Проверки без моделей не подтверждают доступные квоты; старый зелёный лог относится только
к своей версии. Логи, стенограммы, разовые отчёты и временные артефакты в Git не сохраняются.

Отдельный [реестр глобального сбора плодов](harvest-2026-09-20.md) связывает накопленные
исследования и патчи с проверками, решениями и коммитами dev.
