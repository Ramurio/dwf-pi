# Важные ошибки и ограничения

[Индекс](README.md) · [Проверки](development.md)

## Ошибки и защитные контракты: обязательные инварианты

| Ошибка | Что сохранять | Регрессия в `tests/` |
| --- | --- | --- |
| Панель другой установки считала supervisor умершим | Проверять сохранённые script/`owner`/`run`/store; до записи PID искать тот же процесс | `run-controller`, `run-store` |
| Приведение типов SDK меняло JSON до проверки | Проверять исходные аргументы, не преобразованный результат | `pi-worker`, `execution-plan` |
| Выбранный skill разворачивался на диске, но не попадал даже в список для модели | Непустые skills требуют итогового `read` или `bash`; отказ до авторизации, чтение зафиксированного файла проверяется через SDK | `skill-delivery`, `pi-worker` |
| Гонка пауза → продолжение выглядела как ошибка исполнения | Типизированный отказ допуска без новой активации | `pause-resume-admission` |
| Потеря завершённого обновления OAuth при отмене | Сохранить обновление под блокировкой, не считать вызывающую операцию успешной | `oauth-refresh-abort` |
| Повреждённый пресет ломал общий список | Изолировать плохую версию и показать диагностику | `preset-corruption` |
| Старый расход терялся или считался дважды | Сохранять исходную базу учёта и известные суммы без выдуманной полноты | `legacy-usage`, `usage-pages`, `task-usage` |
| Ручное восстановление оставляло активным автоматический повтор | Замещённое решение о повторе не может допустить новую попытку | `retry-reconciliation` |
| Публичная схема `workflow.patch` не включала `id` | CLI/MCP принимают одну опубликованную форму запроса | `public-patch-schema` |
| Сигнал `bash` или неизвестный код выхода считался успехом | Сигнал отдельно от кода; неизвестный выход — ошибка | `bash-signal`, `bash-signal-worker` |
| Выбранный переход оставался от другой ветки | Выбор и панель деталей привязаны к запуску и области активации | `graph-transition-scope` |
| Рёбра графа перекрывались | Отдельные маршруты и корректная геометрия | `graph-layout-overlap` |
| Обмен с исполнителем терял итог/зависал | Ровно один `result`/`error`; учитывать exit без `close` | `process-client` |
| Неверная `outputSchema` обнаруживалась слишком поздно | Проверка графа компилирует итоговые схемы `agent`/`await`/`reuse` до исполнителя | `campaign-schema`, `graph`, `execution-plan` |
| Описание смешивало создание валидатора и проверку значения | `createOutputValidator(schema)` возвращает функцию; её вызов проверяет значение без изменения входа и возвращает JSON-копию | `execution-plan`, `campaign-schema` |
| Отключение повторов сессии оставляло HTTP-повторы SDK | Один запрос провайдера без скрытого повтора, Codex по SSE | `provider-response`, `provider-retry`, `repair-core` |
| Риск повторной записи ради исправления JSON | Режим `submit-only` не возвращает исходные инструменты и не повторяет задание | `output-repair`, `retry-worker` |
| Сохранение ошибки дочерней ветви при восстановлении `collect` | Зафиксированные результаты ветвей читаются из журнала без повторного исполнения | `collection`, `wave5-crash-collect` |
| Ответ старому `await` после продолжения задачи | Старый запуск ограждён; нельзя открыть новую работу старым ответом | `continuation` |
| Чтение usage исполняло свойства или принимало унаследованные поля | Только собственные перечислимые данные; отклонённый отчёт не пишет учёт | `usage-boundary`, `run-store` |
| Дырявые JSON-массивы и изменение буквальных данных схемы | Плотные индексы; преобразование схем сохраняет данные и имена свойств | `json-array-boundary`, `public-schema-literals` |
| Устаревший повтор и недоступное состояние выбора узла | Повтор относится к текущей попытке незавершённого запуска; выбор отражён в `aria-pressed` | `terminal-retries`, `graph-node-accessibility` |
| Запоздавший снимок возвращал старый статус и форму ответа | Только актуальный запрос текущего выбора меняет снимок, ошибку и состояние связи; старый 401 не перезагружает страницу | `graph-view-observation` |
| Подтверждение отмены относилось к уже другому запуску после браузерного «Назад» | Смена запуска закрывает диалог; подтверждение связано с ID и посещением, поздний ответ управления не меняет сообщение нового запуска | `graph-view-observation` |
| Панель предлагала ответ отменяемому или заменённому запуску | Ограничение видно до отправки; у источника продолжения есть переход к новому запуску, обычная пауза разрешает сохранить ответ | `graph-view-observation`, `continuation` |
| Одинаковые вопросы параллельных ветвей выглядели одним ожиданием | Видны путь активации и ID; отдельный черновик остаётся привязан к своему ожиданию | `graph-view-observation` |
| Отсутствующий отчёт показывался как нулевой расход | Нет отчётов — «н/д», частичная сумма обозначена, настоящий нулевой отчёт остаётся нулём | `monitor`, `graph-view-observation`, `usage-contract` |

Имена наборов проверяйте в актуальном `tests/`; важен исполняемый сценарий,
а не историческое число успешных тестов. Подробности — в профильных документах.

## Не путать с багом или готовой возможностью

- `succeeded` — техническое завершение, а `accepted` — решение задачи. Совет ревьюеров
  с ошибкой провайдера или `inconclusive` не даёт `approve` от этой ветви.
- SDK `read` не гарантирует чтение одной очень длинной строки. Подготовьте текстовые
  части и манифест по [инструкции](authoring.md#read-boundaries); «всё прочитано» без них недоказуемо.
- Нельзя копировать один `.sqlite` активного WAL-журнала и считать это актуальным
  резервным снимком. Используйте [согласованный снимок](development.md#sqlite-backup).
- Heartbeat и PID по отдельности не доказывают живость. Уже работающая старая панель
  не получает новое исправление без перезапуска.
- После аварии `agent`/`check` эффекты могут быть неопределёнными; обычное продолжение
  не разрешает повтор. Частичные регистрации Git и утраченные файлы требуют отдельной
  инспекции/ремонта; [восстановление](reconciliation.md) описывает границы.
- Среда исполнения не редактирует топологию активного графа, не изолирует права ОС
  и не предоставляет гарантированный откат внешних эффектов.
- `usage` может быть неполным при оборванном ответе; оценка стоимости SDK не равна
  платежу по подписке. Неизвестное значение нельзя заменять нулём.
- Каталоги провайдеров меняются. Выбранный `thinking` и реально наблюдаемый уровень
  рассуждений различаются; не обещайте поддержку по названию модели или подписки.
- Общий пул SDK-сессий не внедрён. Независимые `bash`-процессы могут пережить SIGKILL
  общего процесса; условия безопасного внедрения — в [эксперименте](development.md#experiments).

## Открытое наблюдение: нестабильные процессные тесты

**Инвариант:** исполнитель без завершённого stdin отменяется по `disconnect` с кодом 130;
конкурирующие `resume` создают одного supervisor; восстановление не повторяет дочерние
записи/коммиты; передача управления через CLI возвращает один корректный ответ и тот же
запуск при повторной доставке.

На macOS arm64 с Node 26.8.1 в полном `npm test` наблюдался таймаут 10 с у
`worker child cancels incomplete stdin on disconnect` (`tests/pi-worker.test.ts`).
В повторном полном прогоне этот тест прошёл, но возникли таймауты ожидания SIGKILL
`merge-last` и завершения восстановленной интеграции (`tests/git-recovery-crash.test.ts`),
`Concurrent resume exited null` (`tests/run-controller.test.ts`) и статус `null` вместо 0
при передаче управления через CLI (`tests/skill-handoff.test.ts`). Последовательный
прогон всех четырёх наборов прошёл 80/80; отдельный pi-worker — 57/57. Это **не исправление**
и не подтверждение стабильности полного набора. Причина не установлена; высокая нагрузка
машины наблюдалась, но её причинная роль не доказана. Исполнение и таймауты не менялись.

Воспроизведение и сравнение (без моделей, только временные проверочные данные):

```sh
npm test
node --import tsx --test --test-concurrency=1 tests/pi-worker.test.ts tests/git-recovery-crash.test.ts tests/run-controller.test.ts tests/skill-handoff.test.ts
```

Для установления причины недостаёт записи времени spawn/ready/`disconnect`/exit,
сигнала завершения и состояния проверочных процессов в момент отказа, а также сравнения
на минимальной поддерживаемой Node 22.19 и при контролируемой нагрузке. Успешный отдельный
прогон не заменяет этих доказательств; нельзя просто увеличивать таймауты или приписывать
сбою конкретную гонку процессов без воспроизведения.

## Проверки, которые нельзя преувеличивать

Тесты SDK без моделей не подтверждают реальные квоты/права аккаунта. Тесты геометрии
интерфейса не заменяют все ручные сценарии масштаба/темы. Историческое ревью или лог
относится к конкретной версии, а не автоматически к текущему дереву.
