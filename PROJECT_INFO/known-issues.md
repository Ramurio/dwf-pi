## Не путать с багом или готовой возможностью

- `succeeded` — техническое завершение, а `accepted` — решение задачи. Совет ревьюеров
  с ошибкой провайдера или `inconclusive` не даёт `approve` от этой ветви.
- SDK `read` не гарантирует чтение одной очень длинной строки. Подготовьте текстовые
  части и манифест по [инструкции](authoring.md#read-boundaries); «всё прочитано» без них недоказуемо.
- Нельзя копировать один `.sqlite` активного WAL-журнала и считать это актуальным
  резервным снимком. Используйте [согласованный снимок](development.md#sqlite-backup).
- Heartbeat и PID по отдельности не доказывают живость. Уже работающая старая панель
  не получает новое исправление без перезапуска.
- После аварии `agent`/`check` эффекты могут быть неопределёнными; обычное продолжение
  не разрешает повтор. Частичные регистрации Git и утраченные файлы требуют отдельной
  инспекции/ремонта; [восстановление](reconciliation.md) описывает границы.
- Среда исполнения не редактирует топологию активного графа, не изолирует права ОС
  и не предоставляет гарантированный откат внешних эффектов.
- `usage` может быть неполным при оборванном ответе; оценка стоимости SDK не равна
  платежу по подписке. Неизвестное значение нельзя заменять нулём.
- Каталоги провайдеров меняются. Выбранный `thinking` и реально наблюдаемый уровень
  рассуждений различаются; не обещайте поддержку по названию модели или подписки.
- Общий пул SDK-сессий не внедрён; условия — в [эксперименте](development.md#experiments).
  При этом уже штатный SDK запускает `bash` в отдельной группе на POSIX. Она может
  пережить SIGKILL отдельного pi-worker, а не только общего процесса. Пустая группа
  обёртки не доказывает остановку shell-команд: [границы учёта](reconciliation.md#groups).
- URL панели сохраняет выбранное выполнение/попытку; масштаб, раскрытие и черновики
  существуют в памяти вкладки и сбрасываются при полной перезагрузке. Архивная попытка
  может требовать загрузки следующей страницы; её результат не подменяется текущим.
- Старые планы без авторского `label` показывают технические ID. Старые журналы без
  трассы/допуска не позволяют доказать причину перехода к следующему проходу; совпадение
  времени не служит заменой. Страничная трасса явно показывает, что ещё не загружено.
- История отображается порциями по 100, полоса обзора — последние 20 с общей численностью;
  все записи доступны. Полной виртуализации SVG/дерева пока нет: очень крупная схема
  продолжает требовать построения всех узлов, хотя ветки дерева раскрываются лениво.

## Открытое наблюдение: нестабильные процессные тесты

**Инвариант:** исполнитель без завершённого stdin отменяется по `disconnect` с кодом 130;
конкурирующие `resume` создают одного supervisor; восстановление не повторяет дочерние
записи/коммиты; передача управления через CLI возвращает один корректный ответ и тот же
запуск при повторной доставке.

На macOS arm64 с Node 26.8.1 в полном `npm test` наблюдался таймаут 10 с у
`worker child cancels incomplete stdin on disconnect` (`tests/pi-worker.test.ts`).
В повторном полном прогоне этот тест прошёл, но возникли таймауты ожидания SIGKILL
`merge-last` и завершения восстановленной интеграции (`tests/git-recovery-crash.test.ts`),
`Concurrent resume exited null` (`tests/run-controller.test.ts`) и статус `null` вместо 0
при передаче управления через CLI (`tests/skill-handoff.test.ts`). Последовательный
прогон всех четырёх наборов прошёл 80/80; отдельный pi-worker — 57/57. Это **не исправление**
и не подтверждение стабильности полного набора. Причина не установлена; высокая нагрузка
машины наблюдалась, но её причинная роль не доказана. Исполнение и таймауты не менялись.

Воспроизведение и сравнение (без моделей, только временные проверочные данные):

```sh
npm test
node --import tsx --test --test-concurrency=1 tests/pi-worker.test.ts tests/git-recovery-crash.test.ts tests/run-controller.test.ts tests/skill-handoff.test.ts
```

Для установления причины недостаёт записи времени spawn/ready/`disconnect`/exit,
сигнала завершения и состояния проверочных процессов в момент отказа, а также сравнения
на минимальной поддерживаемой Node 22.19 и при контролируемой нагрузке. Успешный отдельный
прогон не заменяет этих доказательств; нельзя просто увеличивать таймауты или приписывать
сбою конкретную гонку процессов без воспроизведения.

## Проверки, которые нельзя преувеличивать

Тесты SDK без моделей не подтверждают реальные квоты/права аккаунта. Тесты геометрии
интерфейса не заменяют все ручные сценарии масштаба/темы. Историческое ревью или лог
относится к конкретной версии, а не автоматически к текущему дереву.

### Дополнительные проверенные границы

- Управляемые Git-деревья отклоняют `assume-unchanged` и `skip-worktree` до
  снимка или слияния: эти флаги скрывают изменения от обычного `git status`.
  Снимите их явно после проверки файлов; runtime не меняет индекс за пользователя.
  Игнорируемый вложенный репозиторий считается локальным содержимым, которое
  нельзя перезаписывать интеграцией. Проверки: `workspaces`.
- Ошибка cleanup сохраняется вместе с исходной причиной и не становится
  собираемым результатом ветки. Прерывание ждёт закрытия процесса/pipe и сохраняет
  отказ cleanup. Неопределённая вторичная причина требует явного решения при
  continuation. Проверки: `run-runtime`, `collection`, `retry-policy`.
- Повтор исходного `run.start` после continuation возвращает прежний ID, не
  снимая fence. Повтор continuation завершает лишь окно create-before-reserve;
  paused/interrupted/terminal цели не возобновляются доставкой запроса.
- `ps` выполняется с UTF-8 locale независимо от locale наблюдателя. Это защищает
  Unicode-пути от ложной смерти процесса, но не обещает атомарности POSIX
  проверки PID и последующего сигнала при реальном переиспользовании PID.
- SQLite `SQLITE_FULL` сохраняет исходную причину после автоматического rollback;
  вторичный отказ доступен в `error.rollbackError`. Проверки сбоя процесса и
  WAL-backup не являются испытанием отключения питания или неисправности диска.
- Результаты abort/refresh проверяют кооперативную отмену. Успешная запись новых
  credentials до более поздней ошибки возможна; ошибка авторизации не означает,
  что credentials обязательно остались прежними. На SDK 0.85.1 детерминированный
  SIGKILL после усечения файла, до записи новых байтов, оставляет пустой файл в
  обоих путях FileAuthStorageBackend. Проверено только на фиктивных данных;
  это не испытание реальной ротации токенов или отключения питания.
  Локального исправления этой аварийной записи пока нет: простая замена через
  rename меняет inode/жёсткие ссылки и не сохраняет ACL, а дополнительный журнал
  требует общего протокола с другими установками pi. Автоматический откат к старым
  credentials недопустим: после ротации они могут уже не работать.
- Исправление первого создания auth-файла закрывает отдельную гонку до захвата
  блокировки; sync/async используют одинаковый stale=30 секунд и heartbeat через
  15 секунд. Это устраняет прежний захват async lock синхронным процессом уже после
  10 секунд. Остановка владельца дольше lease, задержка event loop или скачок часов
  остаются ограничением proper-lockfile: постоянного fencing token здесь нет.
  Исправление не делает последующую запись устойчивой к SIGKILL. Участники
  должны использовать исправленный SDK и один путь блокировки; старая установка
  pi по-прежнему может создать файл вне lock. Разные пути через ссылки могут иметь
  разные блокировки. Существующие mode/ACL и семантика записи через ссылки сохранены.

- Recovery-осмотр требует корректные UTF-8 имена файлов и цели симлинков.
  Непредставимые байты отклоняются до выдачи digest: замена символом `�` могла
  скрыть реальный файл как отсутствующий. Mac обычно отвергает такие имена при
  создании; отказ осмотра отдельно проверен на Linux. Корректные Unicode-имена,
  включая начальный BOM и настоящий `�`, сохраняются без нормализации.

## Граница snapshot → commit

Opt-in worktree tree constraint закрывает успешную выдачу B при одобренном A.
S/P/C включают selector approvedArtifactRevision; старые frozen планы остаются unguarded.
Postcheck может обнаружить drift уже после создания commit: ошибка сохраняет этот эффект,
а не отменяет его. Guard не проверяет качество ревью и игнорируемые файлы, не изолирует ОС
и не блокирует внешних writers. `succeeded` по-прежнему не означает `accepted`.
Регрессии: `workspaces`, `worktree-constraint`, `run-runtime`, `operation-record`, `graph`.

## Локальный цикл не публикует PR

`implementation-loop` v1 принимает только локальную работу. Для PR нужны отдельные
сверка истории Git, remote head/base, проверенный CI SHA и контролируемое восстановление
неопределённых push/merge; успех локального check не подтверждает их. Worktree — не
sandbox, read-only ревьюеры не выполняют Bash. Prepared план не замораживает HEAD и
файлы cwd. Тесты authoring/guards: `tests/recipe-authoring.test.ts`; старые
`tests/implementation-recipes.test.ts` и `tests/prepared-start.test.ts` проверяют
совместимость и доставку.
