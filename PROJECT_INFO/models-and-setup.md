# Установка, модели и диагностика

## Установка команды и skill

Из копии репозитория с Node >=22.19.0:

```sh
npm ci
node --import tsx scripts/setup.ts
```

Установщик создаёт две ссылки: `~/.local/bin/dynamicwf` на исполняемый файл этой копии
репозитория и `~/.agents/skills/dynamic-workflows` на переносимый пакет инструкций (skill).
Sudo не нужен. Установщик не устанавливает зависимости, не получает учётные данные,
не меняет настройки запуска оболочки или управляющего приложения. Добавьте `~/.local/bin`
в `path` сами; результат сообщает `binOnPath`. Копия репозитория и её `node_modules` остаются
установленным приложением. После переноса повторите установку с `--replace`:
заменяются только ссылки, никогда обычные файлы/каталоги.

```sh
node --import tsx scripts/setup.ts --bin-dir /path/to/bin --skills-dir /path/to/skills
```

Повтор с другим `--skills-dir` открывает тот же skill другому управляющему приложению.
`~/.agents/skills` — распространённое соглашение, не гарантия автоматического обнаружения.
Приложение может прочитать [SKILL.md](../skills/dynamic-workflows/SKILL.md) напрямую.
Если ссылки на каталоги не поддерживаются, скопируйте **весь** skill и обновляйте копию
после изменений. Для `config.skills` также нужен реальный каталог, а не ссылка в корне.

Команда работает из любого рабочего каталога:

```sh
dynamicwf catalog.list <<'JSON'
{}
JSON
dynamicwf workflow.schema <<'JSON'
{}
JSON
dynamicwf watch --run run-… --once
dynamicwf mcp
```

Исполняемый файл регистрирует установленный `tsx/esm/api` и импортирует CLI/watch/MCP
в том же Node, не создаёт процесс-обёртку транспорта и не меняет `cwd`. Независимо от
родителя работают только supervisor и исполнители. Для MCP укажите абсолютный путь
исполняемого файла и аргументы `["mcp"]` в обычной stdio-конфигурации приложения;
при необходимости добавьте `--store /absolute/state.sqlite` и `--cwd /absolute/workspace`.
Проект не редактирует эти настройки автоматически. CLI не требует настройки MCP;
рабочую директорию можно передать в запросе подготовки.

Состояние по умолчанию — `$DYNAMICWF_HOME/state.sqlite`, иначе `~/.dynamicwf/state.sqlite`.
`--store` выбирает другой журнал. Удаление двух установленных ссылок не удаляет копию
репозитория, журнал, пресеты и не останавливает графы. [Наблюдение](observation.md).

## Каталог и авторизация

`catalog.models` (MCP `catalog_models`) возвращает `{models,issues}`: конкретные
`provider`, `id`, поддерживаемые `thinkingLevels`, исходные и эффективные возможности
входа/результатов инструментов. Отсутствие метаданных означает `unknown`, не запрет.
По умолчанию используется локальный авторизованный кэш: без вызовов модели и сетевого
обновления каталога. `{ "refresh": true }` явно обновляет каталог встроенного xAI.
Читайте `issues`; запись модели не доказывает права аккаунта на любой запрос.

Модели и авторизация исполнителей берутся из локального pi независимо от вызывающего
приложения. Установка CLI/skill не переносит учётные данные между продуктами и не
превращает название подписки (например Heavy) в ID модели API. Учётные данные не входят
в граф, запрос исполнителя, план или публичный каталог. Пользовательские расширения не загружаются.

Grok использует встроенный провайдер pi `xai`: авторизация в pi через `/login xai`
→ **Use a subscription**. Для Grok 4.6 задайте `{ "provider": "xai", "id": "grok-4.6" }`,
если он доступен в каталоге. `xhigh` и возможности изображений берутся из установленного
pi. Сохраняются обычные зафиксированные инструменты, `submit_result`, продолжение сессий,
проверки изображений и учёт расхода.

## Возможности и `thinking`

Различайте исходную способность модели принимать изображения и эффективные возможности
маршрута входа/результатов инструментов: `supported`, `unsupported`, `unknown`.
Заявленная поддержка изображений сама по себе не подтверждает поддержку активного
инструмента/транспорта. `config.requirements.inputModalities` / `toolResultModalities`
принимают `text` и `image`. При требовании `image` подготовка и исполнитель требуют
подтверждённую поддержку обоих эффективных путей. Для обычного текста дополнительных
требований не нужно. Исполнитель берёт безопасное пересечение зафиксированных и текущих
возможностей, а не расширяет разрешения при изменении каталога.

Доступные, запрошенные и разрешённые уровни рассуждений сохранены раздельно в
`reasoning.available/requested/resolved`. Явный неподдерживаемый `thinking` — ошибка
подготовки; адаптироваться может только неявное значение роли по умолчанию.
Нельзя переименовать `xhigh` в `high`. Наблюдаемый `sentReasoning` берётся из фактического
тела запроса на границе fetch; настроенный уровень не подставляется вместо наблюдения.

Изображения из `read` проверяются до попадания в историю сессии. На маршруте только
для текста или с неизвестными возможностями возвращается исправимая ошибка инструмента,
а не неявная отправка изображения. Поддерживаемые MIME — PNG/JPEG (`image/jpg`
нормализуется в `image/jpeg`). Проверяются base64, реальный формат и декодирование.
Перед каждым запросом модели дополнительно проверяется вся накопленная история,
в том числе восстановленная сессия и раунд исправления формата. Количество и
суммарная длина проверяются до декодирования; отказ происходит до отправки запроса.
Границы для встроенных изображений: 32 изображения, 16 MiB base64-символов на одно
и 24 MiB суммарно, сторона до 8192, до 12 000 000 пикселей, до 48 MiB декодированных
данных. Это защитные границы формата, не бюджет графа. Точные проверки/уменьшение
размера — `src/image-boundary.ts`. Для больших текстовых материалов нужна другая
подготовка: [границы `read`](authoring.md#read-boundaries).

## Локальная диагностика

`system.doctor` (MCP `system_doctor`) принимает необязательный `cwd`, абсолютный или
относительный к рабочему каталогу сервиса. Возвращает выбранные `cwd`/`store`, отдельные
проверки, безопасные ID моделей/ошибки каталога и независимые признаки готовности:

| Поле | Предпосылки |
| --- | --- |
| `pureRuns` | Поддерживаемые Node/POSIX, читаемый рабочий каталог, доступное постоянное хранилище |
| `agentRuns` | То же плюс хотя бы одна авторизованная модель в кэше |
| `grok` | То же плюс модель `xai`; это не проверка реальных прав/Heavy |
| `workspaceWrites` | То же плюс права ОС на запись и проход по рабочему каталогу |

Проверяются Node >=22.19.0, группы процессов POSIX, рабочий каталог, место состояния,
Git и кэш моделей. Отсутствие Git сообщается отдельно: графы без Git возможны.
Без моделей доступны чистые вычисления и узлы `check`. `:memory:` не подходит для
исполнения в отдельном процессе.

Проверка состояния создаёт и удаляет временный соседний каталог с пробной записью,
но не открывает/мигрирует/меняет выбранную БД и её служебные файлы, не создаёт
отсутствующий родительский каталог. Она не проверяет схему или содержимое существующей
БД. Рабочий каталог проверяется через права ОС без создания файлов, кроме случая,
когда он также содержит место пробной записи состояния. Готовность — предпосылки,
не гарантия исправности любого графа.

Doctor не вызывает модели и сетевое обновление, не возвращает учётные данные,
пути файлов авторизации или сырые ошибки провайдера. Обе входные MCP-схемы закрыты;
у doctor нет переключателя обновления — он есть только у `catalog.models`.
Переданный сервису `availableModels` даёт детерминированный каталог обоим инструментам,
даже при явном обновлении, без обращения к внешней авторизации.

Версия Node проверяется целиком: допускаются стабильные версии от 22.19.0,
необязательный префикс `v` и метаданные сборки после `+`. Предварительные версии,
неполная запись и посторонние символы отвергаются. Это проверка готовности в
`system.doctor`; правила запуска среды исполнения не меняются. Регрессии: `doctor`.

## Проверки

- `tests/setup.test.ts`: установка во временные каталоги, ссылки и CLI.
- `tests/doctor.test.ts`: отсутствующие пути без создания, неизменность существующей БД,
  ошибки платформы/версии/каталога/хранилища, подстановка моделей, схемы и метаданные MCP.
- `tests/native-xai.test.ts`, `tests/repair-core.test.ts`: встроенный каталог, вызовы
  инструментов `responses`, PNG/JPEG, изменение размера, запросы xhigh, продолженные
  сессии, изменение возможностей и ошибки HTTP с подставным транспортом, без вызова модели.
- `tests/capabilities.test.ts`, `tests/image-boundary.test.ts`, `tests/request-observation.test.ts`:
  границы модальностей и наблюдения запросов.

`npm run test:repair:live` делает реальные вызовы встроенного xAI с временными изображениями
и по умолчанию пишет очищенные доказательства в `scratch/repair-live-latest.json`.
Не запускайте его ради документации; тесты без моделей не подтверждают реальные квоты.

### Выбранный skill и ручной вызов

`config.skills` фиксирует и доставляет содержимое, но не доказывает его применение
моделью. SDK сохраняет смысл frontmatter `disable-model-invocation: true`: такой
файл не рекламируется модели в списке доступных skills. Dynamicwf не снимает
флаг и не выполняет ручное `/skill:...` автоматически. Для обычного выбора
процедуры используйте skill без этого флага (или со значением `false`).
Исторические планы с ручным skill остаются читаемыми и исполнимыми; это доставка
файла, а не гарантия его автоматического использования. Парные проверки
`pi-worker` закрепляют варианты `true` / `false` / отсутствие поля.
