# Трасса маршрутизации

Планы compiler/runtime v3 записывают выбор после каждого завершённого нетерминального
узла. `runtime.route` вычисляет условия в порядке authoring, сохраняет результат
и лишь затем возвращает следующий program counter. `end`/`finish` завершают invocation
и не создают исходящий переход. Выбранное ребро означает решение scheduler; запуск
целевого узла подтверждается отдельной activation.

`RoutingDecision` version 1 содержит source node, выбранный `edgeIndex`/target или
ошибку, причину (`condition`, `fallback`, `no-match`, `error`) и результаты каждого
исходящего ребра: `true`, `false`, `not-evaluated`, `fallback`, `error`.
Первое true прекращает проверку; остальные условия остаются not-evaluated.
Fallback применяется после всех false независимо от своего места в массиве.
Неверный тип/отсутствующая ссылка прекращает маршрутизацию, а не выбирает fallback.

Индекс ребра — нулевой индекс в `graphs[graphId].edges` замороженного плана.
В браузере «ребро #N» показывает индекс + 1. Номер исходящего перехода на подписи
схемы — отдельный локальный порядок узла. Полная идентичность решения:
run + activation key (scope, graph, node, visit). Динамические map/parallel invocations
не смешиваются даже при одинаковых node IDs и visit. Запись содержит attempt source
activation, время, cursor и decision. Исходные значения всего input/контекста в
trace не копируются; условие можно сопоставить с frozen AST и outputs в run.inspect.

## Журнал и восстановление

`workflow_transitions` хранит одну запись на исходную activation. Запись и событие
`route.decided` фиксируются одной транзакцией. Owner token обязателен для записи;
повтор того же решения не добавляет запись, конфликтующее решение отвергается.
После восстановления используется сохранённый переход, без повторного вычисления.

Если supervisor умер между checkpoint исходного узла и записью перехода, scheduler
восстанавливает node outputs из checkpoints, вычисляет переход и записывает его.
Завершённое внешнее действие не повторяется. Если условие упало, source activation
может быть succeeded, а run — failed: это различные факты, оба сохраняются.

V1/v2 планы запускаются с исходными source/hash и прежним chooseEdge. Их API возвращает
`summary.supported:false`; причины исторических переходов не реконструируются из
цветов/порядка activations. Snapshot старого run также не получает вымышленные рёбра.

## API и браузер

```sh
dynamicwf run.trace <<'JSON'
{"id":"run-RETURNED-ID","after":0,"limit":100}
JSON
```

MCP `run_trace` принимает те же поля. Ответ: `planHash`, `summary`, `records`,
`nextAfter`, `hasMore`. Cursor эксклюзивный, страницы 1–1000 записей; ID неизвестного
run и неверный cursor — ошибки. Summary считает все сохранённые решения, ошибки
и выборы рёбер по graph/scope. Чтение не меняет журнал и не запускает recovery.

Вкладка «Трасса» показывает решения в порядке записи, условия и их результаты.
Страницы сохраняются при переключении run/вкладки; текущий просмотр подхватывает
новые записи после прочитанного хвоста. «Показать источник на графе» выбирает graph,
scope и source node, перемещает камеру и показывает это решение в inspector.
Зелёные связи имеют записанные выборы в текущем scope; синяя связь относится к
выбранной записи. Счётчики находятся в SVG title и доступны без цветовой интерпретации.

Серые/непосещённые узлы не получают статус skipped только из-за отсутствия activation.
Полная временная шкала, сравнение проходов, версии критериев и артефакты остаются
отдельными этапами. Трасса объясняет решение условия, а не доказывает качество policy.

## Проверка

`tests/routing-trace.test.ts`: условный приоритет/fallback/short-circuit, строгие ошибки,
реальный цикл, SIGKILL и replay без повторных записей/действий, gap между action и
route checkpoint, map scopes, pagination, совпадение API и графовых счётчиков,
атомарность с event failure injection и исходный v2 golden plan.
Golden v1 также остаётся в полном наборе. Compiler tests проверяют generated TS.

В in-app browser на `spikes/ui-await-smoke.ts` проверены пустая трасса до ответа,
false condition→fallback→rejected, ссылка на source, правильное ребро/счётчик и
inspector. Временный fixture не использует модели или пользовательский journal.
