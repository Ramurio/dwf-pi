# Локальный интерфейс workflow

Постоянная закладка по умолчанию: **http://127.0.0.1:4380/**.
Панель показывает старые и новые запуски из общей базы dynamicwf.

```sh
# Один раз на macOS: включить запуск панели при входе в систему и запустить её сейчас
dynamicwf ui --install
# Открыть/найти панель без настройки автозапуска:
dynamicwf ui
# Получить сохраняемую ссылку на конкретный запуск:
dynamicwf ui --run <run-id>
# Выбрать другую базу/порт при первоначальной настройке:
dynamicwf ui --install --store /path/to/state.sqlite --port 4380
# Отключить автозапуск и остановить только панель:
dynamicwf ui --uninstall
# Временный независимый просмотрщик (другая база, случайный порт, Ctrl+C для выхода):
dynamicwf ui --foreground --store /path/to/other.sqlite --port 0
```

Обычная команда печатает ссылку и завершается. Сервер работает в фоне; повторная
команда использует уже работающий экземпляр. `dynamicwf graph` — альтернативное
имя той же команды. База и порт сохраняются в `~/.dynamicwf/dashboard/config.json`;
без явных параметров используются сохранённые настройки, при первой настройке —
общая база и порт 4380. Если панель уже работает с другой базой/портом, команда
объясняет конфликт: сначала `--uninstall`, затем новая настройка, либо отдельный
`--foreground`. Занятый другим приложением порт не подменяется случайным.

На macOS `--install` создаёт пользовательский LaunchAgent: он поднимает панель при
входе в систему и восстанавливает её после падения. Исходный каталог проекта и Node
должны оставаться доступны; после переноса проекта выполни `--uninstall`, затем
`--install` из новой установки. Лог сервера:
`~/.dynamicwf/dashboard/server.log`. На других ОС доступен фоновый режим;
установка автозапуска пока реализована только для macOS.

При выборе запуска адрес становится `http://127.0.0.1:4380/?run=<id>`. Эту ссылку
можно сохранить; обновление страницы и кнопки назад/вперёд сохраняют выбранный run.
Если run отсутствует в этой базе, интерфейс сообщает ошибку, не выбирая вместо него
другой. Закрытие вкладки, терминала или перезапуск панели не отменяет workflow:
их исполнением управляют отдельные supervisor-процессы.

## Что доступно

- Итог задачи отдельно от статуса исполнения: решение, причина и evidence.
- Ожидания: причина, вход и схема ответа, JSON-форма с серверной проверкой.
  Ответ на паузе сохраняется до «Продолжить»; черновик переживает обновления страницы
  данными и смену вкладок. Reload пока сбрасывает черновик.

- Список запусков, поиск по названию/ID и переключение между ними. Продолжения
  помечаются в списке; панель задачи показывает task ID, исходный/новый запуск,
  причину и reused digest. Причина рендерится как текст, без HTML.
- Исходный сбой остаётся рядом с активным продолжением. Узел `reuse` ссылается на
  источник и не показывает модель. На вкладке «Токены» можно смотреть расход запуска
  или всей задачи; страницы отчётов сохраняются при переключении связанных запусков.
  В режиме всей задачи строки агентов и исходных ответов открывают producer-запуск
  и его узел, а не ищут тот же id в графе продолжения. Смена на другую задачу
  сбрасывает task usage до отрисовки и не оставляет прошлые totals под новым заголовком.
- **Граф:** блоки со состояниями, токены agent-узлов, стрелки условий и возвратов.
  Колесо меняет масштаб, перетаскивание фона перемещает схему. «Вместить» показывает
  весь граф. Вложенные графы открываются из списка или деталей узла.
- Для графа с несколькими вызовами доступен выбор конкретной ветки. Например,
  reviewer показывает все три ветки council либо только correctness. Число проходов
  и ветки не смешиваются с числом определений узлов.
- **Сейчас:** активные задачи, время и последнее событие pi. Контейнеры скрываются,
  пока внутри них работают дочерние узлы.
- **История:** завершённые проходы, результаты, фильтр агентов и ошибок/замечаний.
- **Токены:** общий расход, вход/выход, доли моделей, расход каждого worker/прохода,
  неполнота отчётов и отдельная оценка SDK. Семантика учёта та же, что у terminal watch.
  Новые запуски показывают также кэш и reasoning при наличии; учёт обновляется после
  каждого ответа модели и сохраняется при ошибке/отмене. Исходные отчёты можно
  раскрыть страницами. [Контракт учёта](usage.md).
- Детали узла по клику: модель/thinking, ветки, проходы, результаты, замечания,
  ошибки и условия переходов.
- Пауза, возобновление и отмена через существующий RunController. Отмена имеет
  отдельное подтверждение с названием и ID запуска. Состояние кнопок зависит от
  фактического статуса; ошибки управления показываются на странице.

Схема показывает возможные переходы, а подсветка пройденных рёбер берётся из
сохранённой трассы для выбранного scope. Структура графа сама по себе не доказывает
выполнение ветки. Цвет блока отражает журнал; замечания и непринятый результат
выделяются отдельно.
Для повторявшегося узла учитывается последний результат каждой ветки, а история
сохраняет предыдущие проходы. Масштаб, выбранный узел и раздел сохраняются при
периодическом обновлении. После перезагрузки страницы run восстанавливается из URL; выбранный узел и масштаб сбрасываются.

Snapshot обновляется примерно раз в секунду, список запусков — раз в три опроса.
Проверка выбранного run использует ту же сверку живости/reconciliation, что
`run.status`. Отсутствие события модели не трактуется как доказанное зависание.
Исходный журнал, CLI/MCP authoring, presets и runtime сохраняют свои интерфейсы;
браузер сейчас предназначен для мониторинга и управления существующими запусками.

## Локальная граница

Сервер слушает только `127.0.0.1`, проверяет точный Host и не включает CORS.
Открытие страницы в отдельной вкладке создаёт HttpOnly/SameSite=Strict cookie;
ключ не попадает в ссылку. Встраивание в чужую страницу запрещено. Запросы из других
сайтов и других локальных origin отклоняются по Fetch Metadata/Origin. Управляющие
POST дополнительно требуют cookie, тот же Origin, JSON и специальный заголовок.
После перезапуска сервера браузер автоматически обновляет страницу и получает новую
сессию по прежнему адресу. Другие локальные процессы с правами пользователя остаются
в доверенной границе; это не защита от вредоносного ПО на самом компьютере.

У CLI отдельный секрет в приватном каталоге настроек: он нужен только для проверки
экземпляра и остановки панели, не передаётся браузеру. Секреты workflow не меняются.
Временный режим `--foreground` сохраняет прежний случайный ключ в пути URL.
Страница не загружает внешние ресурсы; CSP запрещает внешние скрипты и встраивание.
API не отдаёт owner/worker tokens, prompts, credentials, session paths или raw logs.
Названия, условия, результаты и замечания отображаются как текст, без исполнения HTML.

## Проверка

`tests/graph-view.test.ts`, `tests/graph-view-task-scope.test.ts` и
`tests/dashboard.test.ts` проверяют HTTP/local-origin границу, управление,
переключение запусков и граф. `tests/graph-transition-scope.test.ts`
проверяет выбранный transition и scope через DOM и настоящий Chrome fixture.
Для ручной проверки без моделей и пользовательской базы:

```sh
node --import tsx spikes/ui-smoke.ts
```

Откройте напечатанную ссылку; Ctrl+C закрывает fixture и удаляет временную базу.
После обновления кода перезапустите панель: уже загруженный процесс не обновляется
сам. Проверка supervisor использует сохранённую идентичность запуска, поэтому
новая панель может наблюдать workflow из другой установки; старую панель нужно обновить.
