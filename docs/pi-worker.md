# Isolated pi invocation

`src/pi-worker.ts` executes one graph agent invocation through the pinned, actual pi SDK. `src/pi-worker-process.ts` is the child entry point: one JSON `PiWorkerRequest` on stdin through EOF, NDJSON `ready`, curated `event`, then exactly one `result` or `error` on stdout. It accepts extra command-line identity metadata without interpreting it. Provider errors are not copied into the public protocol because they can contain request data or credentials.

The worker uses pi's internal `ModelRuntime` for authentication; no credentials travel in the workflow request or result. It requires the exact authenticated provider/model from the frozen configuration. After session creation it verifies model, thinking and tool allowlist: unsupported thinking levels fail instead of silently accepting pi's clamp. Tests inject a `ModelRuntime` with a deterministic transport; the session, tool loop, event lifecycle and persistence remain real pi.

Global/project settings, extensions, context files (`AGENTS.md`, `SYSTEM.md`, `APPEND_SYSTEM.md`), prompt templates and discovered skills are disabled. In-memory settings disable SDK retries, auto compaction and telemetry. Only frozen selected skill bytes are materialized, under a unique per-invocation resource directory; relative traversal, empty path components, existing destinations and symlink destinations are rejected. The loader receives only these explicit skill paths and verifies loaded identity. Supporting files retain executable permission when requested. This is a reproducibility boundary; the containing local state directory must be controlled by the runtime. It is not protection against a concurrent hostile process mutating the filesystem.

The configured system prompt is preserved and followed by mandatory `submit_result` instructions. The worker supplies the task and JSON input as the user message. `submit_result` validates the raw arguments with the shared strict validator before pi's tool coercion. A missing, invalid or duplicate submission fails the invocation by default, even if the SDK considers the turn settled. An explicitly frozen [output repair policy](output-repair.md) can instead request another formatting round in the same session, with only `submit_result` active. An accepted result stops subsequent model turns. A subsequent assistant error or abort invalidates the result. Usage counts only assistant messages generated by this invocation, including repair rounds and continued sessions.

`continue-node` may reopen the exact supplied session file in the same workspace; a fresh worker rejects continuation. Each new invocation needs a separate resource directory, while continuation retains the prior transcript path. The supervisor must ensure only one invocation owns a continued session at a time. Transcripts are private artifacts containing task/tool data; public events contain only lifecycle types, recognized tool names, and status, not arguments, outputs or credentials.

Cancellation closes admission first, clears steering and follow-up queues, aborts the session, awaits prompt/session settlement and disposes it. SIGTERM, SIGINT and supervisor IPC disconnect use the same path. Cancellation while waiting for stdin closes input as well. The process disconnects its IPC channel on termination. Node can emit `exit` without `close` after the parent disconnects IPC; supervisors must not rely on `close` alone to confirm termination.

Permissions are tool-level: `read-only` forbids bash/edit/write. `workspace-write` chooses the working directory and tool grant but is **not an OS sandbox**; pi's bash and filesystem tools can reach outside it. OS isolation and write coordination belong to the supervisor/workspace layer. The worker does not invent a Grok Heavy alias or assume subscription access maps to an API model.

Verification: `node --import tsx --test tests/pi-worker.test.ts`. Tests cover strict and exact-once output, errors after submission, full async settlement, queued-message cancellation, session continuation, resource isolation and unsafe paths, model/thinking mismatch, child framing and parent-disconnect cleanup. They make no live inference calls.
