# Переносимость skill и интерфейса

Проверено 2026-09-08 по первичным источникам. Ниже отделены свойства стандартов
от предлагаемого устройства проекта; готовой совместимости ещё нет.

## Подтверждённые факты

Agent Skills определяет каталог с `SKILL.md`, YAML metadata и Markdown-инструкциями.
Обязательны name и description; references/scripts допускаются. Поле compatibility
описывает требования окружения. `allowed-tools` экспериментально: поддержка
различается между реализациями. Следовательно, skill нельзя считать единым механизмом
выдачи разрешений во всех harness. [Спецификация](https://agentskills.io/specification)

MCP tools задают inputSchema и необязательную outputSchema; результат может иметь
structuredContent. Сервер должен соблюдать объявленную выходную схему, клиенту
рекомендуется проверка. Для совместимости предусмотрено дублирование JSON текстом.
Аннотации инструмента являются подсказками, а не исполнением политики доступа.
Structured tool result не означает schema-constrained генерацию моделью.
[Спецификация tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

Репозиторий Serverless Workflow при проверке перенаправляется в
Open Workflow Specification. Это отдельный declarative DSL и полезный источник
идей для блоков, но не доказательство того, что его runtime подходит для pi.
[Первичный репозиторий](https://github.com/open-workflow-specification/specification)

## Собственные выводы для проекта

Переносимость следует проверять на трёх слоях: агент понял skill; harness умеет
вызвать CLI либо MCP; общий backend применил одинаковый контракт и права.
Поддержка формата SKILL.md одним клиентом не доказывает остальные два слоя.

Предлагается один сервис команд, над которым CLI и MCP являются транспортами.
Skill опирается на CLI с JSON stdin/file как общий знаменатель и объясняет MCP
при его наличии. При harness без автоматического discovery skill пользователь
может явно передать тот же файл агенту с доступом к shell. При отсутствии любого
tool execution одного текста skill недостаточно для запуска pi.

Installation хранит runtime/config/credentials один раз вне конкретного harness.
Подключение skill в несколько discovery-директорий — установка ссылок или копий,
а не отдельная инсталляция движка. Setup должен проверить каталоги и конфликтующие
версии; нельзя молча перезаписывать чужие skills либо settings.

Контрактная совместимость проверяется вызовами тех же authoring операций из CLI
и MCP с одинаковыми ошибками и IDs, а затем сквозным запуском. Реальную проверку
агентского UX из нескольких harness следует отражать отдельно от теста транспорта.
