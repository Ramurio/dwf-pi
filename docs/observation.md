# Общее представление запуска

`RunController.snapshot(id)` сначала проверяет известные процессы через `observe`,
затем получает activations и строит `projectRun` из `src/observation.ts`.
Этот результат используют service/CLI/MCP, список и детали запусков в браузере,
интерактивный и append-only watch. Наблюдение не перезапускает workflow; подтверждённая
смерть supervisor и workers фиксируется как interrupted тем же механизмом controller.

`presentation` содержит:

- `status`, `desired`, `statusLabel`, `terminal` — выполнение и намерение оператора.
- `taskOutcome`, `outcomeLabel`, `accepted` — приёмку с общей legacy-совместимостью.
- `activeKeys` — конкретные исполняемые задачи; ожидания и контейнеры с активными
  детьми не удваивают счётчик. На paused/interrupted/terminal активных задач 0.
- `waitingKeys` — await activations, которые сейчас ждут ответа. Исторические
  незакрытые requests после interruption/cancel отдельно доступны через run.waits.
- `liveness` — состояние, подпись, факт присутствия supervisor, число живых workers
  и время проверки процессов.

| Liveness | Значение |
| --- | --- |
| supervised | Найден supervisor с ожидаемой идентичностью |
| orphaned-workers | Supervisor не найден, но записанные workers ещё живы |
| unresolved-groups | Worker не найден, но в записанной группе есть процессы; принадлежность требует проверки |
| launching | Есть reservation без подтверждённого PID, смерть не установлена |
| stopped | Проверка не обнаружила процессы запуска |
| unknown | Проекция построена без проверки ОС; флаги и время равны null |

Устаревший heartbeat не переводит запуск в interrupted. Terminal outcome также
не служит доказательством отсутствия процессов. Проверка ОС и чтение SQLite —
последовательные наблюдения, а не общая атомарная транзакция; следующий poll может
уточнить состояние. При ошибке проверки ОС клиент получает ошибку, а не выдуманный
stopped. Owner/worker fencing tokens в presentation не входят.

Новые workers резервируют идентификатор до spawn. Пока PID ещё не сохранён,
`observe` ищет такой процесс по скрипту и полному worker-token в списке процессов ОС.
Найденный worker учитывается в `orphaned-workers`, удерживает owner от повторного
запуска и доступен для явной отмены. Чтение не создаёт исторический PID checkpoint.
Несколько reservations используют один снимок списка процессов за наблюдение.
Отсутствующий процесс не считается живым только из-за записи reservation.
Смерть wrapper ещё не доказывает завершение всех его потомков или внешних действий.
Новые group checkpoints сохраняются до подтверждения отсутствия активных членов.
`unresolvedGroups` содержит key/attempt/groupPid, PID/PPID/state и явное
ownership=unverified; команды и environment не читаются для этой проверки.
Такие группы блокируют освобождение owner, повтор и успешное завершение.
Поскольку номер группы мог быть переиспользован, автоматическая отмена по одному
этому номеру не выполняется. После исчезновения процессов fenced update отмечает
группу empty; повторные polls не дублируют событие. Zombie не считается активным,
неизвестное состояние ОС остаётся потенциально активным. Подробности и ограничения
для escaped descendants и старых записей: reconciliation.md.

В browser/CLI/MCP одно представление `unresolved-groups`; заголовок нетерминального
запуска без живого supervisor показывает «Проверка процессов», сохраняя намерение
pause/cancel. Browser раскрывает PID и связь с задачей. `unresolvedGroupProcesses`
считает кандидатов отдельно от `workersAlive`; они не выдаются за подтверждённых
workers или успешно продолжающееся выполнение.

Browser получает готовые подписи статуса/результата/живости; run list показывает
результат приёмки после завершения. Время проверки не входит в render signature,
поэтому очередной poll без смысловых изменений не закрывает evidence и не пересоздаёт
форму. Терминальный append-only вывод также не печатает новые строки из-за часов.
Ждущие запросы отображаются с причиной и wait ID. Paused structural rows можно
видеть как контекст продолжения, но они не считаются работающими задачами.

Проверки: `tests/observation.test.ts` — матрица процессов/приёмки/паузы и соответствие
проекций; `tests/await-outcome.test.ts` — watch как первый наблюдатель после SIGKILL,
совпадение service и browser list/snapshot на реальном ожидании. Native browser
fixture пережил смерть supervisor во время ввода, сохранил черновик и завершился
после ответа под тем же run ID. Обзор с группами, trace/timeline и оптимизация
чтений/проверки большого числа процессов остаются отдельными направлениями.
