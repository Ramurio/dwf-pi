# Repair 2026-09-13 — CORE and CONTINUATIONS

Design for Grok image transport, effective capabilities, trusted diagnostics, project-local pi 0.85.1, and explicit task continuation lineage.

## Adapter identity (CORE)

The subscription bridge still loads only the reviewed `pi-xai-oauth@1.5.2` helper files (`models.ts`, `catalog.ts`, `responses.ts` and their import closure). Package version is not treated as proof of contents. `src/adapter-identity.ts` freezes SHA-256 digests of that closure plus the reviewed SDK trio `pi-ai` / `pi-coding-agent` / `pi-agent-core` `0.85.1`. Load-time and lazy transport loading re-hash the files. Manifest read/parse failures, unsupported identity/version, missing or tampered helper files, and SDK version mismatch all record a trusted `adapter-content-mismatch` observation with dispatch `not-dispatched` before throwing, so lazyStream/checkProvider keep a local configuration error instead of a generic provider failure.

Peer range on the helper still excludes 0.85. Support is this project's contract tests, not an upstream compatibility claim.

## Image transport (CORE)

`resizeImage` is the native async SDK ABI. PNG and JPEG are accepted, including progressive JPEG, after a bounded structural inspect and an actual native decode. Marker-only or entropy-invalid JPEGs, empty-pixel PNGs, surplus inflated IDAT, illegal scanline filters and truncated images are rejected locally. GIF/WebP/BMP fail with `image-unsupported` / `image-invalid`. The SDK `read` tool is wrapped using the intersection of frozen and current effective capabilities, so a catalog that later becomes text-only or unknown cannot admit images from a previously frozen vision plan. Explicit image requirements fail before execution; unexpected image reads return recoverable tool feedback instead of destroying the session.

## Capabilities and diagnostics (CORE)

Catalog/prepare publish raw model input separately from effective workflow input/tool-result capabilities. Authenticated helper provenance `authenticated-input-modalities` with `[text,image]` is supported; the same provenance remains unsupported for text-only catalogs, and omitted or `conservative-default` metadata stays unknown. Optional `config.requirements` make prepare reject unknown/unsupported image needs. New capability-bearing plans were v8; v1–v7 keep original keys (`tests/fixtures/legacy-v7-plan.json`). Closed diagnostic subcodes travel on `ExecutionFailure.diagnostic` without prefix-matching helper strings. After a writer, effects stay unknown even when that turn never left the process.

## Task lineage (CONTINUATIONS)

New ordinary starts create a task and root membership atomically. Existing unlinked rows stay unlinked; adopting them records a later association and does not claim the original launch had a task ID. Lineage is never inferred from timestamps, cwd or workflow name.

`run.continuation.inspect` returns the source checkpoint, related runs, reusable succeeded outputs and blockers. `run.continue` requires `preparedId`, a mandatory idempotency key in the global start-key namespace, source identity/checkpoint/planHash, workspace digest, actor/reason/evidence, input and exact reuse bindings. Exact redelivery returns the same run before rereading the workspace. Conflicts roll back without orphan tasks, runs or receipts.

A durable fence on the source prevents resume, reconcile and a second successor. Pause is copied to the successor, not lifted on the original. Cancel remains run-specific. Unknown writer effects, including unfinished running or interrupted side-effect activations on a stopped run, require an explicit `retain-effects` disposition; continuation does not fabricate an accepted output or consume recovery retry permission. Uncertain writers also need a parseable operation record. Continuation reuses recovery's read-only worktree/allocation/integration inspectors and refuses unresolved ownership, missing child workspaces, locked registrations and invalid integration state before receipt creation and again on first admission. Inspection of sealed history remains read-only and does not authorize retry. Reused null JSON outputs are valid when both schemas accept null; revision fields are read only from object values.

Public status, graph snapshot, task inspect and HTTP/MCP projections omit continuation input and canonical request bodies. Exact continue redelivery of a paused successor returns the same paused run without launching. A genuine first admission re-hashes the inspected source workspace; a digest mismatch refuses resume even after a reserve-before-spawn crash. A reserve flag is not writer progress; after a real side-effect activation the original inspect digest is not reapplied. Browser task-vs-run token view pages the task ledger and does not label a stopped successor as active.

## Result reuse (CONTINUATIONS)

Compiler/runtime v9 adds a pure `reuse` node (`bindingId`, strict `outputSchema`). Prepare freezes the schema. `run.continue` loads the original producer activation rather than trusting copied metadata, compares source and producer outputs, and binds inspected output/schema digests. Inspection's `schemaDigest` is the source activation's schema; `producerSchemaDigest` is the original producer contract when one exists, otherwise null. A schemaless producer is not relabelled as the current source or target schema. Binding `sourceSchemaDigest` is checked against the inspected source schema; `producerSchemaDigest` is checked only against a real producer schema. Reused reviewer verdicts must keep artifact/criteria identity and cannot approve a different revision in continuation input. Runtime returns that snapshot without a model invocation. `run.start` rejects a reuse-bearing plan. Reuse of a reuse node keeps the original producer. v1–v8 plans keep their hashes (`tests/fixtures/legacy-v8-plan.json`).

## Task usage and UI (CONTINUATIONS)

`task.usage` aggregates distinct linked run ledgers. Reused outputs add zero SDK usage. Per-run pages and attempt accounting remain. CLI/MCP/watch/browser show task links, reason/plan change and reused digests. Reasons render as text. The original failure stays visible beside an active continuation. Whole-task agent and per-response links open the producer run and activation; switching to another task invalidates prior task totals before render and binds fetched usage to the selected task identity.

## Authoring (CONTINUATIONS)

The dynamic-workflows skill distinguishes effective capabilities from raw model ads, snapshots selected skills including research-resource subtrees that actually exist, asks for external research/QA to be supplied as input/evidence, decomposes substantial work into stages without forcing ceremony on small graphs, reports run IDs immediately, and uses `run.continue` instead of ad hoc saved-JSON replacement. Inspection authorizes nothing; `run.reconcile` is explicit and separate.

## Limitations

pi-xai-oauth 1.5.2 peers still exclude 0.85. Native Codex image entitlement remains unknown unless the catalog says so. Continuation cannot certify arbitrary external side effects; actor evidence is attestation. Historical runs created before these tables have no invented lineage.
