# Результаты Grok-кампании и перенос в продукт

Состояние на 19 сентября 2026. Это рабочий реестр результатов: `accepted` у исследовательского запуска означает принятую проверку или отчёт, а не автоматически исправленный продукт.

## Что уже получено

- 180 тематических source-audit отчётов: материал для проверки гипотез, не 180 доказанных дефектов.
- Лаборатория: 36 кандидатов для 12 контрактов, 2469 конечных примеров. Это результаты стендов, не интеграция всех вариантов.
- Волна 4: семь пакетов перенесены в проекты; [исправления и проверка](grok-campaign-results-2026-09-19.md).
- Волна 5: 17 запусков с исходом `accepted`. Из 15 пакетов кода/проверок **11 предложили production-изменения**, **4 не потребовали исправления**. Ещё два запуска — эксперименты SDK и скилла.

## Первая порция волны 5

Перенесены шесть пакетов. У каждого есть регрессия, падавшая на исходном коде, независимое Grok-ревью кандидата и дополнительный разбор перед переносом.

| Пакет | Проект | Поведение после изменения |
| --- | --- | --- |
| B02 | dynamicwf | Повтор той же заявки `run.continue` после потери ответа возвращает прежний ID, даже если файлы уже изменились. Повторная доставка не запускает работу; для оставшегося queued successor нужен `run.resume`, который по-прежнему проверяет workspace. |
| C08 | dynamicwf | Нулевой placeholder SDK после ошибки/обрыва ответа означает неизвестный расход, а не подтверждённые ноль токенов. Полученные ненулевые отчёты сохраняются. |
| D03 | dynamicwf | `run.reconcile accept` сохраняет полноту ранее учтённого расхода. Синтетическое принятие результата не создаёт новый вызов модели или запись расхода. |
| E01 | dynamicwf | Ошибка CLI/MCP сообщает `operationIndex` (с нуля) для ошибочной операции patch и ожидаемую/фактическую revision при конфликте. |
| F05 | dynamicwf | Переход из истории/отчёта токенов выбирает конкретную ветку активации, сохраняя scope. |
| I09 | remote-pi | Esc после переподключения останавливает и bash, и агентный ход. Потеря связи не отображается как подтверждённая отмена команды. |

Перенесены точные проверенные файлы; до записи содержимое основных проектов сверено с исходными снимками кандидатов. Предшествующие изменения сохранены. Файлы, SHA-256 и резервные копии: `~/.dynamicwf/campaigns/grok-20260918/wave5/integration-batch1/manifest.json` и `before/`. Перенос в рабочее дерево не означает commit, push или обновление уже запущенного процесса.

Проверка совмещённых изменений:

- TypeScript: без ошибок.
- dynamicwf: общий `npm test` выполнил 467 проверок; 466 прошли, одна обнаружила старое ожидание трёх нулевых usage-report для HTTP 429/503/401 без отчётов провайдера. Родительская интеграция обновила `tests/provider-retry.test.ts`: нулей нет, для каждой из трёх попыток есть `usage.unavailable`, полнота остаётся false. Проверки числа запросов, статусов, задержек и Retry-After сохранены. Повторный прогон этого файла вместе с C08/D03: **11/11**, без пропусков. Остальной production-код после общего прогона не менялся; второй полный прогон не выполнялся.
- remote-pi: полный набор **125** прошедших JS-тестов и **41** прошедший Python-тест; соответственно 4 и 6 прежних пропусков. Новые проверки I09 не пропущены.
- Родительское изменение существующего retry-теста отдельно отмечено в манифесте; оно не приписывается независимому ревью предыдущего кандидата. Живой SSH и визуальный браузерный прогон этой порцией не выполнялись.

## Вторая порция волны 5 — перенесена

| Пакет | Итоговое поведение | Границы |
| --- | --- | --- |
| B01 | Намерение check/worktree сохраняется в одной транзакции с допуском активации. После падения до запуска есть данные для явного reconcile. | Автоповтор неизвестных эффектов не разрешён. Agent/integrate и исторические журналы без operation не мигрируются. |
| C04 | Типизированная ошибка OAuth/auth до отправки запроса становится безопасной setup-ошибкой с указанием на повторную авторизацию. Отмена при refresh остаётся отменой. | Реальный xAI refresh не вызывался; проверены отказ, успешное обновление и отмена на подставном OAuth. |
| I03 | Чтение кадра ограничено размером. Oversized кадр заменяется явным `rpi_frame_error`; ожидающие RPC завершаются ошибкой с неизвестным результатом, без повтора. Исправный клиент остаётся подключённым. | История >40 MiB всё ещё не доставляется. Ошибочный кадр нельзя безопасно связать с одним request ID, поэтому отклоняются все текущие ожидания. Медленный клиент с переполненной очередью отключается, не блокируя остальных. |
| I04 | `rpi_error` получает возможность отправиться перед закрытием сокета; зависший получатель принудительно отключается через секунду. Оборванный UTF-8 на EOF распознаётся как неполный ответ. | Доставка ошибки не гарантируется мёртвому соединению. Секунда ограничивает drain сокета, а не выполнение модели. |
| I05 | Транспорт фиксирует незавершённый assistant-префикс на границе `get_messages`; UI восстанавливает его перед событиями после снимка. Завершённая история не проигрывается повторно. Подтверждённая смена сессии очищает старые события. | Префикс до attach недоступен. Источник префикса — существующий буфер 4096 событий; это не неограниченный серверный replay. |

Родительская интеграция доработала I03/I04/I05: модельный I03 молча терял oversized кадры; I04 не ограничивал ожидание заблокированного `sendall`; I05 проигрывал всю очередь live-событий поверх снимка и мог дублировать уже завершённые сообщения. Финальные варианты проверены новыми сценариями, но не выдаются за точные ревизии прежнего независимого Grok-ревью. Для B01 добавлен ранний выход, чтобы не сканировать worktree-активации у остальных типов узлов.

Итоговая совместная проверка: **481/481 dynamicwf**, TypeScript без ошибок; **138 прошедших JS-тестов remote-pi**, 4 прежних пропуска; **45 прошедших Python-тестов**, 6 прежних пропусков. Общий прогон dynamicwf включает исправления первой порции, Git-crash/reconcile и новые crash-регрессии. Новый OAuth-тест проверяет отмену до допуска модели. RPC-проверки включают ограниченное чтение, сохранение следующего кадра, отсутствие повтора команды после потерянного oversized ответа и завершение writer при зависшем клиенте.

Полные журналы, снимки файлов до переноса, манифест и отдельные патчи проектов: `~/.dynamicwf/campaigns/grok-20260918/wave5/integration-batch2/`. Живой SSH и провайдеры не использовались. Для загрузки local UI нужна новая сессия; серверные RPC-изменения требуют обновлённого runtime и нового broker. Уже работающие пользовательские процессы не перезапускались.

## Подтверждённые инварианты — не объявлять багфиксами

| Пакет | Что проверено | Остаток |
| --- | --- | --- |
| B03 | Проверенный путь retry не смешивает результат предыдущей попытки с новой. | Регрессии перенесены; это не доказательство безопасности произвольных прямых вызовов store. |
| G01 | Записанная revision критериев сохраняется при reuse; несовпадение отвергается. | Исторический вердикт без criteria остаётся без criteria. Более строгий контракт требует отдельного решения. |
| crash-supervisor | Сохранённый checkpoint не повторяется; незавершённый внешний эффект требует явного reconcile/retry. | Регрессия с SIGKILL своих процессов; не exactly-once для shell. |
| crash-collect | Settled worktree под parallel/collect не выполняется повторно после паузы/падения; отмена не становится успешным envelope. | Проверен parallel, не map; отдельное покрытие Git commit/add уже существует. |

Во всех четырёх пакетах новые проверки прошли и на baseline. Production-правки для этих гипотез не потребовались. Все четыре набора регрессий перенесены и включены в итоговые 481 тест.

## Эксперименты

**Настоящий xAI SDK.** Партии 1/4/8/16 сессий в одном Node, четыре отдельных Node и отмена одного из четырёх запросов. 36 ответов успешны, один намеренно отменён; остальные при отмене продолжили работу. Все партии прошли проверки собственных маркеров. У партии 16 сессий сэмплированный пик RSS процесса — около 348 MiB. Учтено 455 926 токенов; отменённый запрос имеет неполный учёт. Это расход SDK-эксперимента, отдельно от agent-node ledger и финального анализа.

Пул в production не внедрён. Tools и compaction не упражнялись; конкурентный OAuth refresh не подтверждён. Один прогон под нагрузкой не измеряет устойчивый throughput или лимиты провайдера. [Предыдущий офлайн-эксперимент](session-pool-experiment.md) использовал другую методику и подставной inference.

**Скилл, исходная проверка.** Четыре свежих автора готовили JSON-запросы, которые стенд исполнял настоящим CLI на no-model графах. Loop и await прошли сразу; simple и fan-out — после исправления `expr` на `value` у transform. Это проверка авторинга с replay, не свободная работа coding-agent в терминале. Схема в стенде была одной длинной строкой и могла обрезаться read-инструментом.

**Правка по результатам Grok.** В `skills/dynamic-workflows/references/authoring.md` добавлены компактные примеры transform/map/setEntry и рекомендация сохранять большую схему многострочным JSON. Обе схемы с документированными узлами проверены настоящим `applyPatch` в завершённых графах; `quick_validate.py` прошёл. Установленный скилл ссылается на эту папку, поэтому отдельного копирования при установке не требуется. Для нового испытания подготовлен полный многострочный schema response и точные фрагменты `$defs` с индексом; исходные следы предыдущего испытания сохранены.

Повторный запуск: `run-e54b9620-dadd-47a5-a728-f703323ddde1`, четыре свежих Grok 4.6 xhigh и синтез. Артефакты: `~/.dynamicwf/campaigns/grok-20260918/skill-retest-20260919/`. Изменились одновременно документация и подача схемы: даже улучшившийся результат нельзя приписать только тексту скилла. Стенд по-прежнему исполняет JSON-запросы авторов через CLI, а не проверяет свободную интерактивную работу coding-agent.

Результаты исполнения: **4/4 с первой попытки** — simple, fan-out, loop, await (ранее 2/4). Для каждого случая сохранён один первый trial с `passed=true`; идемпотентная повторная доставка start вернула тот же ID. У loop есть повторный visit; у await — реально созданный и разрешённый wait. Манифест фактов и ограничения: `skill-retest-20260919/verification.json`. Один прогон не даёт статистической оценки надёжности.

Запуск вместе с итоговым синтезом завершён: `succeeded`, решение `accepted`. Синтез предложил дополнительные примеры finish/await/условных рёбер, но названные в предложениях «провальные запросы» — иллюстрации, а не наблюдавшиеся ошибки этой серии. Они не перенесены автоматически. Ответ `run.resolve` может ещё показывать waiting, пока supervisor продолжает выполнение; стенд отдельно дождался конечного результата. Это также не обнаруженный сбой.

**Следующая проверка пула.** Добавлен офлайн-тест четырёх `executePiWorker` с одним runtime, реальными read/write, разными cwd/session files и одним обновлением тестового OAuth через штатное файловое хранилище. Вместе с прежними lifecycle-проверками: **15/15**, TypeScript без ошибок. Production-runtime не менялся. Методика и оставшиеся условия внедрения — в [отчёте эксперимента](session-pool-experiment.md#условия-перехода-к-production-пулу).

## Порядок дальнейшего переноса

Перед сохранением в GitHub повторный общий прогон dynamicwf прошёл **482/482**, TypeScript — без ошибок. remote-pi повторно прошёл **138 JS + 45 Python** (прежние 4 + 6 пропусков). Дополнительные две POSIX-проверки пула проходят отдельно: отмена настоящей bash-команды не мешает соседу; SIGKILL общего Node оставляет detached-команды живыми, что подтверждено эффектом после аварии. Это препятствие для внедрения простого общего процесса, а не реализованная защита. Подробности и оставшаяся задача внешнего надзора — в [эксперименте пула](session-pool-experiment.md#отмена-инструмента-и-авария-общего-процесса).

1. Решение о production-пуле после оставшихся проверок tools, lifecycle и refresh; текущих измерений и офлайн-тестов недостаточно для миграции. Примеры скилла и повтор авторинга выполнены.
2. Отдельные будущие улучшения: доставка истории больше лимита, серверный replay префикса до attach и покрытие admission-gap для agent/integrate. Это оставшиеся ограничения, не незавершённый перенос пяти пакетов выше.
