# L02: сохранение завершённой OAuth-ротации

Добавлена типизированная обёртка CredentialStore, включённая в
createWorkflowModelRuntime для переданного store и штатного файлового store.
read/list/delete делегируются без изменения. Для modify caller signal
пересылается отдельному persist signal только до первой строки callback под
исходным lock. После входа callback отмена больше не прерывает сохранение;
после успешного modify caller.throwIfAborted сохраняет отказ отменённого вызова.
Listener снимается в finally. Исходный signal OAuth refresh остаётся у SDK.

Нет повторной записи, CAS после unlock или обхода SDK-проверок compromised lock.
Гарантия требует корректного CredentialStore с сериализованным callback.
Она не восстанавливает токены, если refresh бросил исключение, не вернул пару,
процесс погиб или файловая запись/владение lock нарушены. SDK может отклонить
внешний abort race раньше завершения persist; это не означает потерю записи.

Изолированный loader разрешает ESM dependency относительно проектного модуля,
проверяет имя, точную версию 0.85.1 и API AuthStorage и импортирует private entry
по package-local URL. Глобальный pi и private runtime.credentials не используются.
Обновление SDK требует пересмотра этого контракта; node_modules не изменён.

Проверки без сети и пользовательских auth/config: временный authPath, fake OAuth
в настоящем runtime (default file и переданный memory store), отказ caller при
сохранённой новой паре, повторное чтение без ротации, pre-abort, отмена ожидания
занятого lock, исключение mutation, два дочерних процесса с IPC-барьерами,
проверки отсутствия вымышленных токенов в ошибках/metadata/выводе процессов.
Ожидание persist — по условию с deadline, не фиксированным sleep.

Успешны: oauth-refresh-abort, wave5-c04, native-xai и npm run typecheck.
AGENTS.md в текущем worktree отсутствует; packet L02 прочитан.

## Повторная проверка после review

Добавлены два сценария настоящего createWorkflowModelRuntime с default file
store: refresh бросает исключение без новой пары при переданном caller signal;
отдельно caller отменяется, пока refresh ещё выполняется. Проверяются один
refresh, исходная ошибка/отмена, неизменность access и refresh и всего файла.
Завершение операции подтверждается повторным захватом того же SDK lock
с callback без записи, а не ранним завершением внешнего abort race.
Production-код не менялся: замечание относилось к отсутствию regression proof.
