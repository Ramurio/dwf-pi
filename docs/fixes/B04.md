# B04: отказ допуска при pause → resume

Контрольный запрет `beginActivation` теперь возвращает `RunNotAcceptingWork`
с исходным текстом и полями `desired`/`status`. Другие отказы не изменены.
`JournalRuntime.step` повторяет допуск через существующие step/retryGate/gate
только для этого типа, до исполнения work, при прежнем владельце и отсутствии
cancel. Проверка текста регулярным выражением удалена. Политика retry,
supervisor, worktree admission и поведение уже запущенных процессов не изменены.

## Доказательство

Детерминированная обёртка первого beginActivation запрашивает pause, вызывает
оригинал и в finally выполняет resume до обработчика Effect. Проверено:
два допуска и входа в gate, ровно один work, успешная попытка №1 без истории
неудачных попыток. В вариантах cancel и смены владельца сохраняется именно
исходный объект типизированного отказа, повторного входа в gate нет.
Definition-changed остаётся обычной исходной ошибкой. Обычная ошибка work
с похожим текстом и типизированная ошибка уже допущенного work не повторяются,
даже когда состояние стало paused; попытка №1 завершается failed.

Это доказательство допустимого порядка событий, а не измерение частоты живой
гонки. Тесты локальные, без провайдеров и credentials; SQLite только временная
тестовая. AGENTS.md в текущем worktree отсутствует; packet B04 прочитан.
