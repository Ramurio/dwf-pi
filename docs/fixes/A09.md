# A09: исходный JSON на границе SDK

В `executePiWorker` строгий результат сохраняется отдельным клоном `acceptedOutput`; SDK получает другой клон. Публикация происходит только в execute после checkAdmission. Отсутствующий снимок вызывает ошибку; после публикации, schema failure и в начале каждого repair снимок очищается.

Offline scripted fixture проходит полный SDK-loop без живых провайдеров, с вымышленными credentials. Проверены required nullable string/integer/boolean и type-union: null отличается от пустой строки, 0 и false. Проверены optional null и отсутствие optional поля, duplicate submit, невалидный repair и последующий свежий результат. Отмена в beforeToolCall происходит после prepare и SDK-валидации: hook видит преобразованный null → "", но worker завершается cancelled, не возвращая результат. Сохранены отрицательные проверки integer-string, лишнего и отсутствующего обязательного поля.

No-change:
- `createOutputValidator`: строгая Ajv-валидация без coercion остаётся прежней.
- Раннее отклонение неизвестных keywords: регрессия подтверждает configuration failure до обращения к модели.
- Advertised outputSchema не переписывается: тесты сравнивают схему инструмента в transport context с исходной.
- SDK-валидация остаётся включённой; nullable не запрещается.

Ограничения nullable object/array не исследованы этим исправлением и не объявляются устранёнными.

Проверки: `node --import tsx --test tests/pi-worker.test.ts tests/output-repair.test.ts tests/campaign-schema.test.ts` — 60/60; `npm run typecheck` — успешно. AGENTS.md в текущем worktree и его родительских каталогах отсутствует.
