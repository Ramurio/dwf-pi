## Исправление

Точка потери subtotal — `projectUsage`: ledger sum заменял metadata.usage.
Теперь последний проверяемый immutable pre-ledger архив задаёт version 1 baseline
с subtotal и throughAttempt. Все ledger attempts должны быть позже этой границы.
Архивные cumulative snapshots не складываются. Неизвестный live metadata subtotal
без архивного доказательства не используется; пересечение также отклоняется.
Baseline восстанавливается из архива при повторной проекции смешанного журнала.
История и реальные SDK reports не меняются. beginActivation сохраняет metadata
и предварительно архивирует старый checkpoint; accept переносит baseline.

Существующих summarizeUsage/summarizeTaskUsage достаточно: legacy остаётся partial,
earlierAttempts не скрывается, optional cost/cache сохраняют известные subtotals
и partialFields. SDK cost не равен счёту подписки. Массовой миграции нет.

## Повтор после review request_changes

Ошибка ревью воспроизведена до исправления: при полностью settled пересекающемся
ledger accept давал usageComplete=true. Добавлен устойчивый
`usageLegacyIncomplete`: обнаруженный legacy расход остаётся неполным независимо
от принятия/отклонения baseline. Флаг сохраняют повторные проекции, retry, reopen
и accept; summarizeUsage учитывает его явно, task summary наследует partial.

Регрессии усилены: unknown legacy на первой попытке без архива; overlap с
complete=1 у пересекающейся попытки; у обоих earlierAttempts=0, но partial=true
после settled ledger, reopen и retry. Accept отдельно проверяется для baseline,
unknown и overlap. All-ledger complete/incomplete accept не изменён.
Первый прогон усиленных тестов был красным; после исправления 10/10 прошли.
