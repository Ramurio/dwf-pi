# Q10 — выбранный переход и scope

## Изменение

Inspector проверяет graphId, исходный nodeId и точное равенство
`JSON.stringify(transition.context.scope) === state.scope`, как SVG для scope.
Обработчики dropdown графа и scope очищают transition до renderPanel.
«Все ветки» (`scope === ""`) не присваивает выбранную запись отдельной ветке.
Исправный selectNode оставлен без изменений; обычный redraw в том же scope
сохраняет выбранную запись.

## Доказательства

`tests/graph-transition-scope.test.ts` исполняет существующий app.js, включая
обработчики trace-кнопок, dropdown, SVG-узла и реальные render-функции.
Отключены только сетевой startup и polling; fixture подставляет два durable
решения A/B с одинаковыми graphId/nodeId и второй граф с повторяющимися узлами.
Проверяются inspector и SVG после A → B, выбор B, «Все ветки», смена графа,
selectNode и повторный render. Отдельная подстановка устаревшего transition
проверяет защиту inspector независимо от сброса dropdown.

- До исправления DOM replay падает: `dropdown must clear transition`.
- После исправления четыре назначенных файла: **27/27**, без пропусков.
- Локальный Chrome headless: тот же replay выполнен на index.html со стилями,
  нативными DOM/SVG и событиями change/click; результат `data-replay="passed"`.
  Ручная визуальная оценка цветов/геометрии и скриншотов не проводилась.
- Без установленного Chrome браузерная часть явно skipped; обязательный
  детерминированный DOM replay продолжает выполняться без браузера.
- `npm run typecheck`: успешно. Изначально отсутствовал экспорт SDK из O07;
  применён уже tracked проектный postinstall
  `node scripts/apply-sdk-bash-signal.mjs` к локальной копии node_modules.
  Новых изменений SDK/patch-файлов не потребовалось.

Команда регрессий:

```sh
node --import tsx --test tests/graph-transition-scope.test.ts tests/graph-view.test.ts tests/graph-view-task-scope.test.ts tests/routing-trace.test.ts
npm run typecheck
```

## No-change: исторические operands

transitionDetails не изменён: отображаются записанные decision/reason/error и
результаты evaluations; определение condition читается из графа и не является
снимком исторических operands. Значения operands не сохранены, поэтому их нельзя
восстанавливать из текущих outputs. Fixture содержит отдельное текущее значение
output и проверяет, что оно не появляется как исторический operand в inspector.
Routing runtime, frozen runner и журналы не изменялись; живые провайдеры не вызывались.
Packet Q10 прочитан; AGENTS.md в worktree и проверенных родительских каталогах
не обнаружен.

## Повтор после testFeedback

Независимый check выявил зависание browser QA: тест отменён через 30 секунд,
а процесс проверки завершился лишь примерно через 1774 секунды. Прежний harness
ожидал завершения Chrome `--dump-dom` через execFile и затем закрытия HTTP-сервера;
это связывало результат replay с завершением процессов/stdio и соединений браузера.

Исправлен именно lifecycle harness, проверки selection не ослаблены:

- Страница после всех прежних assertions передаёт значение `data-replay` через
  POST на свой loopback fixture-сервер; успех принимается только при `passed`.
- Spawn не удерживает stdout/stderr pipes. Нет ожидания самостоятельного выхода
  Chrome. На ошибку запуска/ранний выход проверка падает; отсутствие результата
  ограничено отдельным deadline 20 секунд (общий timeout остаётся 30 секунд).
- В finally завершается только новая изолированная process group браузера этого
  теста, закрываются все соединения fixture-сервера и удаляется временный профиль.
  Пользовательский браузер/профиль не используются.

После исправления команда независимого check
`node --import tsx --test --test-concurrency=2 tests/graph-transition-scope.test.ts`
прошла пять последовательных повторов: каждый 2/2, без skipped/cancelled,
полное время каждого запуска 0,38–0,65 секунды. Затем все четыре назначенных
файла прошли 27/27, TypeScript — успешно. Browser QA выполнен повторно в настоящем
локальном Chrome; ручная визуальная оценка по-прежнему не заявляется.

## Второй testFeedback: недостающая диагностика независимого запуска

Лог `task_tests-1.log` подтверждает другой результат: прежнее длительное
зависание устранено, но браузер в независимом check не прислал результат за
20 секунд. По этому логу нельзя установить, запустился ли renderer, загрузился
ли app.js или возникла ошибка модуля. Локально этот сбой не воспроизведён:
включая запуск той же команды из Python subprocess с DEVNULL stdin, captured
stdout/stderr и новой session (2/2 успешно).

Добавлены диагностические меры без ослабления assertions и без увеличения
таймаутов: bounded stderr Chrome и список запросов fixture включаются в ошибку;
ошибки загрузки ресурсов, JS и unhandledrejection передаются страницею немедленно.
Stderr принудительно закрывается при cleanup, чтобы снова не ждать helper pipes.
Для изолированного Chrome явно отключены proxy и background throttling; это
мера изоляции теста, а не доказанная причина сбоя независимого check.

После этих изменений локально четыре файла снова проходят 27/27 (включая
настоящий Chrome), TypeScript и diff-check успешны. Ручной визуальный QA не
проводился. Устранение именно сбоя из второго testFeedback **не подтверждено**:
нужен повтор независимой проверки с новой диагностикой. Изменять frozen runner,
системный Chrome или настройки пользователя для воспроизведения не предпринималось.

## Третий testFeedback: воспроизведён startup при пустом HOME

Новая диагностика `task_tests-2.log`: `requests=[]`, stderr содержит запуск
GoogleUpdater и ошибки регистрации. Следовательно, app.js ещё не был загружен;
это не падение selection assertions. На этом проходе удалось воспроизвести
тот же симптом локально: прежние launch flags + новый пустой HOME дают timeout
20 секунд, `requests=[]`, CVDisplayLink errors и сообщения GoogleUpdater.
Прежние flags были восстановлены только на время этого контрольного запуска;
затем файл возвращён к исправленной версии.

Chrome теперь запускается с automation/default-browser/component-update flags,
`--password-store=basic` и `--use-mock-keychain`, чтобы тест не ожидал нативных
first-run/keychain диалогов. HOME самого browser child всегда новый и находится
в его временном fixture-профиле: условие воспроизведения теперь включено в каждый
browser regression. Таймауты, все assertions и обязательность browser replay
при установленном Chrome сохранены. В stderr сохраняются начало и конец, чтобы
шум updater не скрывал первоначальные ошибки.

С исправленными flags и пустым HOME: пять последовательных запусков независимой
команды локально — каждый 2/2, 0,38–0,53 секунды; затем четыре файла — 27/27,
TypeScript — успешно. Это подтверждает исправление воспроизведённого startup
сценария, но не заменяет повтор независимого check. Конкретный внутренний блокер
Chrome (например, keychain dialog) отдельно не доказан. Лог контрольного запуска
показывает автоматическую попытку встроенного updater; глобальные настройки и
установка браузера вручную не менялись. Live AI providers не использовались.
