# O07: локальный patch pi-coding-agent 0.85.1

Дефект воспроизводился в установленном SDK: waiter отбрасывал signal, а bash
считал null-код успехом. Tracked unified patch добавляет signal-aware waiter;
старый waitForChildProcess остаётся number/null wrapper. Exit, close и idle-drain
сохраняют сигнал, таймер продолжает продлеваться при позднем выводе.
Локальный shell backend bash проверяет сначала abort/timeout, затем signal и
необъяснённый null; диагностическое сообщение включает накопленный вывод.
Изменены также декларации типов. Другие SDK callers waiter не переведены.

## Установка и удаление

`npm ci` / `npm install` применяют patch через postinstall; при отключённых
lifecycle scripts выполнить `node scripts/apply-sdk-bash-signal.mjs` вручную.
Нужен git в PATH. Установщик допускает только физические пути внутри
cwd/node_modules, строго версию 0.85.1 и точные SHA-256 исходных/исправленных
файлов. Проверяет весь набор до записи; смешанное или неизвестное состояние
отклоняет. Применение выполняется в отдельном staging-каталоге с отсечением
поиска родительского Git-репозитория и очищенными GIT_* переменными. Все четыре
результата проверяются по SHA-256 до записи в SDK и повторно после записи.
Повторное применение ничего не меняет. Patch — долговечный источник,
node_modules — только сгенерированный результат. Глобальные установки не нужны.

При будущем проверенном обновлении SDK сначала подтвердить эти регрессии на
чистой новой версии. Только после подтверждения upstream-исправления удалить
patch, установщик, postinstall и hasInstallScript из lockfile, переустановить
зависимости и снова запустить тесты. Не обходить проверку версии ради обновления.

## Доказательства

80 тестов прошли: bash-signal, bash-signal-worker, pi-worker, process-client;
`npm run typecheck` прошёл. Регрессии охватывают реальный отдельный bash с
SIGTERM, stdout перед сигналом, exit 0/7, timeout, pre-cancel и активную отмену;
waiter close/exit/idle и живой потомок с наследованным stdio и поздним выводом;
чистое применение, повторное применение и отказ при неизвестных файлах/версии.
Offline executePiWorker использует только in-memory вымышленные credentials и
scripted provider: публичное событие tool_execution_end.isError=true, SIGTERM
и stdout доступны в фактическом SDK transcript (публичный event намеренно
не содержит payload).

`src/check-worker-process.ts` — **no-change**: отдельный процессный тест подтвердил
exit 1 и failure process/execution/unknown с SIGTERM. Frozen runner, remote-pi,
глобальный pi и credentials не изменялись. AGENTS.md в worktree отсутствует.

## Исправление после ревью

Устранена зависимость `git apply` от родительского checkout/worktree. Регрессия
создаёт локальный временный Git checkout с вложенным node_modules, подтверждает
Git prefix, затем проверяет фактические байты всех четырёх файлов после чистого
применения и повторного запуска. Отдельно fake git, возвращающий exit 0 без
применения, отклоняется по итоговым хешам, установленный SDK не меняется.

Полный повторный прогон четырёх обязательных файлов и TypeScript записан в
[O07-validation.log](O07-validation.log). В начале лога — SHA-256 установщика,
patch и тестов проверенного состояния (runtime создаёт revision после сдачи).
