# Зафиксированные решения

2026-09-08. Ответы пользователя получены после первоначального исследования.

## Ответы пользователя

- Граф собирается до запуска; есть условия, циклы и динамический fan-out.
  Агент должен иметь возможность приостановить workflow.
- Задачи: кодинг, исследования и операции; сначала локальное выполнение.
- Workflow обязательно переживает закрытие harness как самостоятельный процесс.
- Используемые подписки: Codex Pro и Grok Heavy.
- По умолчанию нет лимитов стоимости, времени, параллелизма или числа итераций.
- Review policy настраивается; council можно составить из нескольких примитивов.
- Человеческих согласований по умолчанию нет.
- Oracle — отдельный проект; сейчас на него не ориентироваться.
- Библиотеки пресетов и глобальная, и проектная.
- Git-изоляцию, сессии и интерфейсы пользователь поручил выбрать агенту.
- Вложенные workflow допустимы. Пауза обязательна, ручное изменение скорее не нужно.
- Референс — опыт использования официального Claude Code, без отдельного репозитория.

## Выбор реализации на основании ответов

Это решения разработчика в делегированной области, не дополнительные ответы пользователя.

1. CLI и MCP используют один application service; переносимый skill обучает этому
   контракту. Ни session ID исходного harness, ни его permissions API не нужны backend.
2. На запуск создаётся отдельный локальный supervisor process; pi workers дочерние.
   CLI start быстро возвращает run ID. Pause останавливает новые активации, позволяет
   текущим закончить; cancel отдельно прерывает активных workers. Статусы различают
   pausing и paused. Возобновить и читать состояние можно из нового harness.
3. Схема активного run неизменна. Редактирование draft/preset порождает новую revision
   для будущего run. Циклы и data-dependent map не являются изменением схемы.
4. Параллельным coding-ветвям выдаются отдельные worktree. Интеграция — явный блок;
   общий workspace допустим при последовательном writer. Конфликт не считается merge.
5. Исполнителю можно продолжать node session в repair-loop; независимые reviewers
   получают свежие сессии. Передача контекста между блоками задаётся bindings.
6. Встроенный каталог: general, researcher, planner, implementer, reviewer, verifier,
   synthesizer, arbiter, orchestrator. Отдельную реализацию oracle сейчас не создаём.
   Расширяемый role registry позволит подключить внешний проект позднее.
7. Лимиты опциональны, `undefined` означает отсутствие лимита. Не вводить скрытый
   maxIterations, бюджет или human approval как обязательный путь. Остановка и pause
   доступны независимо от лимитов. Системная нехватка ресурсов — явная ошибка.
8. Сквозной пример: исследование → план → реализация → council reviewers → исправления
   по findings → повторное review до выполнения заданной policy. Дополнительно
   исследовательский map→verify→synthesize для динамической кратности.
9. Восстановление после reboot/crash реализуется явно, но не объявляется доказанным
   требованием пользователя в том же смысле, что независимость от harness. Неопределённый
   исход внешних эффектов требует reconciliation; нельзя молча повторять запись/API.

## Проверенная доступность окружения

Через `ModelRuntime.getAvailableSnapshot()` обнаружен авторизованный provider
`openai-codex`; позднее узкий provider bridge добавил авторизованный `xai-auth`.
Grok 4.6 прошёл live probe; Heavy ID отсутствует в обновлённом каталоге аккаунта.
Название подписки не приравнивается к конкретному model ID. Секреты в конфигурацию графов не копируются.
Реальные модели фиксируются из каталога установки, без неподтверждённых идентификаторов.

## Техническая проверка перед runtime

Public SDK import pi 0.85.0 в чистой npm-установке потребовал явно добавить
`@earendil-works/pi-server@0.85.0`: coding-agent импортирует его через experimental
modules, но пакет отсутствует в его dependencies. Это закреплённый workaround,
не основание использовать pi-server как наш scheduler.
